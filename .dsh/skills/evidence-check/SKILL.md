# 完成证据核验协议（即「验收点核验」）

`curriculum.yaml` 节点里的 **`验收点`** 字段就是过关标准（原字段名 `evidence`，题目系统重构时正名）。本协议管的是：**拿学生的真实产物去对这几条，对不对得上。**

判断一个节点是否"能独立应用"，以证据为准。证据按可信度排序：

1. **运行结果**：代码或测试真实运行通过
2. **测试代码**：学生自己写的测试覆盖了关键行为
3. **解释能力**：能说清"为什么这样设计、哪里可能出错"
4. **口头确认**：单独出现时不足以判定通过

## 核验流程

- 每个 L3/L4 交付物，对照该节点 `验收点` 字段逐条核验；**实验课（`kind: 实验`）还要对照它 `prerequisites` 里被验收节点的 `验收点`**（实验就是拿目前学到的东西做出东西来，被验收的那几条是真门槛）
- 核验时实际运行（能跑就跑，运行失败即证据不成立），反馈具体报错
- 输出三档结论：`通过 / 部分通过（列出缺哪条）/ 不通过（列出原因）`，并给出"差一步就能过"的具体建议

## 硬的边界

- 结论必须能指向一条具体证据；无法指向时按"不通过"处理
- **不得因为"题是我出的"或"学生说懂了"就判过**——出题与批改是同一个角色，这条是它的防线
- 运行只用于核验，学生的项目代码由学生自己写
