# 课件设计规范

课件的**唯一约束来源**。讲解角色动手前先读本文件；总控验收课件时按本文件核对。分两部分：**必须做到的**（硬要素，缺一不可）与**怎么讲**（倾向，按现场判断）。

# 一、硬要素（缺一不可）

1. **真实场景开场**（自顶向下）
   从学生熟悉的真实场景或真实问题切入，**不先抛定义、不先讲底层细节**。开场要让读者产生"哦，原来是这个问题"的落点感。

2. **术语先来历、后定义**
   任何术语**第一次出现前**，先讲清三件事——① 它要解决什么问题 ② 为什么需要它 ③ 它的历史来历（谁在什么背景下提出、之前怎么做、为什么不够用）——**然后**才给定义。术语中英对照（例：直方图均衡化 / histogram equalization）。

3. **权威教材的深度，不做速成课**
   像权威教材一样把知识体系讲透：讲清前提、推导、边界与反例。**内容长没关系**，简洁不等于浅；宁可一课只推进一点，也不要把体系压成提纲。

4. **引导式实验**（见第三节）
   每个知识点配一个动手实验，用"我带你一步步做"的方式，**不把成品脚本甩给学生**。

5. **配套项目给 3 种以上选择**
   随课程做的项目不能只有一个方案：开课时给出至少 3 个可选项目（难度/方向/兴趣不同），由学生挑；选定后它成为贯穿线索（见第五节）。

6. **来源诚实**
   易变/版本相关的内容必须核对官方文档后再写，标注"依据 X 文档"；稳定基础知识标注"通用基础知识（可自行查证）"。**不为凑引用而引用。**

7. **收尾三件事**：阅读任务（对应教材章节 + 一处权威来源）、**与最终目标的关系**（这段知识在学生的整体目标里处于什么位置）、提问提示（"不懂就把这一段复制回会话，加【提问】标记"）。

# 二、每课固定七步结构

1. **开场**：真实场景 / 故事（硬要素 1）
2. **来历**：术语要解决什么问题、为什么出现（硬要素 2）
3. **原理**：只讲本课所需的数学与机制，配教材式推导与图示
4. **实验**：动手实现 + 可视化（`lab/` 的引导 notebook）
5. **检索练习**：即时反馈测验（浏览器内作答，点选即判）
6. **阅读任务**：教材对应章节 + 一处外部权威来源
7. **回扣目标 + 收尾问题**：与最终目标的关系，留一个促人思考的问题

七步都要有；顺序可按内容微调，但"场景在前、定义在后"不能反。

# 三、实验规范（Kaggle 官方教程风格）

实验做成 **Jupyter notebook**，存 `<subject_path>/lab/NN-主题.ipynb`（NN 与课件编号对应）。

- **教程格**：小步讲解 + 可运行代码，**预执行并保留输出**，学生读到就能看见结果
- **任务格**：标 **▸ 你的任务**，代码留空，由学生亲手写
- **自检**：任务格后跟 `assert` 断言，学生跑通即通过
- **参考答案**：折叠隐藏（`<details>` 或 notebook 的折叠区），做完再展开
- **严禁**：把成品整段脚本直接甩给学生当教学
- 连写版完整脚本只放 `<subject_path>/lab/solutions/`，供做完后回顾对照
- 学生卡壳时：先引导读错误信息、给提示，**不直接给答案**
- 科目首次做实验时确定 Python 环境（venv + 依赖），记进 `<subject_path>/lab/README.md`

# 四、讲法倾向（弱约束，可被覆盖）

这不是检查表，是一组倾向。目标是学生真的听懂，走哪条路按现场判断。

**问题感** — 先让学生感到"这是个什么麻烦"。他知道麻烦长什么样，概念才有落点。

**具体先行** — 例子走在定义前面。能跑的一小段代码、一个生活场景，都可以当入口。

**小步** — 一次给一点。学生消化的速度比讲完的速度重要。

**学生的语言** — 沿用学生自己的说法。他用得上那个词，才算学会。

**参与** — 留出预测、改一行、复述的空间。学生自己动手或开口时，你能看见他卡在哪一层。

**连回项目** — 把知识与他在做的事接上。有去处的东西不容易忘。

**学生反馈的处理倾向**：
- "没听懂" → 换一个更近的例子，或降一层抽象
- "太简单" → 加边界、加取舍、加反例
- 要答案 → 先给线索；还卡再加码
- "有什么用" → 先答用途，再回内容

**覆盖关系**：这些倾向是默认值。学生的明确要求、科目性质、任务紧急度都可以覆盖它们；`MEMORY.md` 里记录的个人偏好优先级最高——那份文件就是这套指引随人调整的地方。

# 五、贯穿线索（课程级，与课件呼应）

每课都要连回三条线索，别让学生学完忘了为什么学：

- **最终目标线索**：每课第七步回答"这段知识与学生的最终目标（`MISSION.md`）什么关系"
- **项目线索**：选定的配套项目从早期就作为实验的固定测试素材，逐课埋线——项目不等到最后才写
- **工具线索**（编程类科目）：亲手实现的算法与现成库（OpenCV/scikit-image 等）的结果对照，知道"标准答案长什么样、为什么长这样"

# 六、复用与骨架（硬约束）

- **先读组件库**：读 `<subject_path>/assets/`（至少 `style.css`、`quiz.js`），已课件必须链接已有组件
- **从骨架拷起**：`<root>/templates/lesson.html`（顶栏、主题开关、提问提示、样式脚本引用都已就位，路径就是课件该用的相对路径），再改标题、编号、节点与正文；**别删主题开关**
- **编号递增**：`NNNN-dash-case.html`，取现有最大编号 +1
- **新组件先写进 `assets/`** 再引用，不内联可复用代码；拿不准是否可复用时，先写进 `assets/` 更稳
- 课件是自包含 HTML（相对路径引用共享层 `../../../assets/`、科目组件 `../assets/`、`reference/`），浏览器直接打开即可用
