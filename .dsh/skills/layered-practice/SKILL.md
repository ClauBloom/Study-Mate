# 题目唯一规范

**全系统的题都按本规范出，且只由 `practice-evaluator` 出**（题面、答案、判分标准、lab 实操题、`solutions/`）。其他角色不碰题目内容：`learning-coach` 只负责把题嵌进课件并决定位置与行文；`lesson-design` 管课件的呈现与要素，不管题目内容。

题目的**数据字段**（选择题与开放题各写什么键）以 `templates/assets/quiz.js` 顶部注释为准——那是渲染器的契约，本规范不重复字段表。本规范管的是：**出什么题、怎么要求、什么算过。**

# 一、四层

四层是默认进阶路径，不是必须逐级走完的台阶：学生已在项目里用过某知识点，可以从高层起步；某层反复卡住，可以退回来补。

| 层 | 类型 | 出题要求 | 通过标准 |
|----|------|---------|---------|
| L1 理解 | 判断/解释/预测输出 | 每题追问"为什么" | 能解释原因，不只给结论 |
| L2 改造 | 修改已有代码观察变化 | 给可运行的 10-20 行代码，指定一处改动 | 能预测改动结果并运行验证 |
| L3 排错 | 真实 bug 定位 | 给含 1-2 个 bug 的代码或真实报错 | 能说出根因 + 修复 + 预防 |
| L4 应用 | 放进真实项目 | 任务挂到项目里程碑，交付物明确 | 代码跑通 + 测试通过 + 能解释取舍 |

**哪一层能用在哪**：概念课（没挂项目里程碑的节点）止于 **L3**；**L4 只出现在挂了里程碑的节点**（它有真实落点）。这条决定课型，见第四节。

**L1-L4 是"题"的词汇，不进页面**：层级用来选出题深度、记进评估记录的 `layer` 字段；课件页面上的题只写题面、选项／参考答案、算过标准，不挂 L 标。**也不要用 L1-L4 去标动手块或跟做步骤**——那些步骤的标题按内容写（如"第 3 步 · 改造"）。

# 二、四种题型

| 题型 | 长什么样 | 判分方式 | 适合的层 |
|------|---------|---------|---------|
| **选择题** | 页内 `.quiz`，点选项即时反馈 + 一句 `why` | 页内自动判 | L1、部分 L2 |
| **开放题** | 页内出题，学生先自己想/写，**参考答案与算过标准点击展开**（不贴回会话） | 学生自评 | L1 追问为什么、L2 预测、L3 找根因 |
| **实操题** | `lab/` 里的留白任务 + 断言 + `solutions/`，学生亲手写代码 | `npm test` 自动判 | L2、L3、L4 |
| **评估题** | 评估时现场出的 1-2 题（开放） | `practice-evaluator` 判 | 按目标层级 |

选题型的原则：**能自动判的优先选择题；要"说清为什么 / 找根因 / 解释取舍"的用开放题；要真跑代码的用实操题。** 开放题必须同时给参考答案与"算过标准"（学生据此自评），缺一不可。

# 三、出题要求

- 题目贴近生产场景与真实报错；"背诵定义"类题目留给学生自查。
- 选择题：选项尽量等长、同句式——别让长度泄露答案（闸门对这条只提示 `WARN`、不阻断）。
- 开放题：答案不唯一时，参考答案要给出可接受的替代方案并写明判断依据。
- 实操题：任务写成可核验的（断言／期望输出／清单），`solutions/` 与任务分开放、做完才对照。
- **题量不设下限**：由出题人按节点重要性定。实操课的题量让位给动手；概念课可以多问几道。
- 每题备好参考答案与常见错误答案，供批改对照。
- 出题前先读该节点的 `objective` 与 `验收点`（过关标准）、学生最近的 misconceptions、目标层级；出题后逐题说明它对的是哪条验收点（**软对照**：不强制全覆盖，没覆盖的在评估记录里写明理由）。

# 四、课型与实操归属

**节点的实操归属由项目里程碑决定**（`progress.yaml` 的 `project.milestones[].nodes`）：

- 节点挂在某个里程碑上 → **实操课**：配整套 `lab/`（教程 + 留白任务 + 断言 + `solutions/`），题目可到 L4；课件动手块的内容由出题人给。
- 没挂里程碑 → **概念课**：不配 `lab`，题目止于 L3；课件里**允许轻量跟做**（敲一条命令、改一行看变化，由讲解角色写），但不落 lab、不算交付物、不算题。

# 五、什么算过

- 结论三档：`通过 / 部分通过（列出缺哪条）/ 不通过（列出原因）`，并给"差一步就能过"的具体建议。
- **每条结论必须指向一条具体证据**（学生的作答原文、运行结果、交付物）；指不出具体证据的，按"不通过"处理。
- **不得因为"题是我出的"或"学生说懂了"就判过**——说懂了不是证据。
- 证据可信度排序见 `evidence-check`（运行结果 > 学生自己写的测试 > 解释能力 > 口头确认）。

# 六、实操题（lab）规范

**载体由总控与学生确定**（盘问时确认，记进 `lab/README.md`）；本节只管载体定下来后怎么做。lab 全部内容（教程、留白任务、断言、`package.json`、`solutions/`、README 的任务部分）都由 `practice-evaluator` 产出，总控写盘；讲解角色不碰 lab。

**通用原则（五条）**：分步引导（一小步讲解 + 立刻动手，不一次抛完整任务）；亲手做（任务留白给学生写，成品只放 `lab/solutions/`）；可验证（断言／测试／期望输出对照／清单勾选）；即时反馈（做完立刻能验，不等 agent）；卡壳先引导（读错误信息 → 提示 → 线索，不给答案）。

**每种载体都要做到**：教程部分带结果（Python 预执行输出，其他语言先跑一遍或贴运行结果）；任务留白并写清"要做什么、怎么算过"（写成 `▸ 你的任务` 这类标记只是常见写法，不是必须的字面要求）；自检可跑（能自动验的写断言／测试，不能的给自查清单）；答案与成品分开放（做完再对照，不提前剧透）。

**结构**：`lab/NN-主题/`（或 `NN-主题.ipynb`）与课件编号对齐；答案统一放 `lab/solutions/`；环境与依赖写 `lab/README.md`。
