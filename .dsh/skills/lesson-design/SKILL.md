# 课件设计规范

**本文件管课件内核与内容写法，不管版式**：怎么分节、标题写什么、例子与代码块放哪，都由讲解角色按内容与学生偏好决定；`MEMORY.md` 的个人偏好优先。页面形态（页头、顶栏、主题开关、脚本）由渲染器统一产出，不在讲解角色的职责里。题目、lab、实验说明页都不归它管（规范见 `layered-practice`）。

## 一、着眼点（弱约束，根据实际情况调整，不必强加内容）

1. **参考**：课件的结构与内容可参考 `RESOURCES.md` 收集到的认可度高的教材；你也可以把缺的来源报给总控（收集归 `resource-scout`）
2. **真实场景**：说清楚某个概念解决的是什么麻烦、什么场景下用得上
3. **术语先来历、后定义**：术语第一次出现时先知道它在历史上为什么被发明，再看到定义；中英对照
4. **深度**：讲透前提、推导、边界与反例，不做速成课；简洁不等于浅
5. **动手**：
   - `kind: 实操` → 引导式实操：任务与断言由 `practice-evaluator` 出、落在 `lab/`；内容文件里对应一个动手块（lab 内容归出题人，位置与引入由你定）
   - `kind: 概念` → 轻量跟做：敲一条命令、改一行看变化、在输出里指出某个东西；不落 lab、不算交付物、分步且每步立刻能看到结果
   - 动手块与跟做步骤的标题按内容写中文阶段名（如"第 3 步 · 改造"）——**不要用 L1-L4 标步骤**（那是题目的层级词汇）

## 二、记忆与难度（弱约束）

分清**流畅度**（当场会复述）与**存储强度**（过段时间还记得住，目标）；用**合意困难**设计：检索练习（回忆而非重读）、间隔（分散到多次会话）、交错（混合相关主题）；难度落在最近发展区。

## 三、贯穿线索

**最终目标**（这段知识与 `MISSION.md` 的关系）；**配套项目**（从早期就作为实操素材逐课埋线）；**工具对照**（编程类：亲手实现与现成库结果对照）。

## 四、复用与骨架（硬约束）

**块名与用途见下表，准确写法以 `<root>/docs/课件内容格式.md` 为准**（本文件不复述语法细节——两份必然漂移）。本文件管**用哪些块、怎么组织一节课**。

| 要讲的东西 | 用哪个块 | 设计口径 |
|---|---|---|
| 一节 | `## 标题` | ≤14 字（进左侧目录）；句式服从内容，一节一个着眼点 |
| 分点、步骤、对照 | `-` 列表 / 管道表 | 对照关系（说法 ↔ 写法 ↔ 边界）用表，其余用列表；列表项不写长段落 |
| 代码与终端 | ` ```lang ` 围栏 | 讲的代码要能跑；语言标签写清楚 |
| 动手与跟做 | `::: practice <层级> \| <标题>` | 按「动手」那条着眼点安排（lab 内容归出题人，位置与引入由你定） |
| 题目位 | `::: quiz <层级> 锚点：<锚点文本>` | 只留位、不写题：题由 `practice-evaluator` 出，锚点文本逐字给它 |
| 提示 / 警告 / 中性提示 | `::: tip` / `::: warn` / `::: note` | 用在真会绊倒学生的地方，不拿它凑版面 |
| 配图 | `::: figure <相对路径>` + `alt:` / `caption:`；示意图 `::: svg` | 池子里挑（见下）；**每张必须有 `alt:`**；`caption:` 写「图 N · 一句话（来源：…）」 |
| 资源与相关课件 | `::: resources` / `::: related` | 只放真会去用的；给不出链接的参考书写成不带链接的条目 |

**一节的组织**：一个 `##` 一节，先场景与来历、再定义、再例子与代码、最后动手或题目位收尾；层级只用 `##` 与 `###`（再深就是该拆节了）。

| 硬约束 | 怎么做 |
|---|---|
| 起点 | 先读 `<subject_path>/assets/` 组件库（复用样式与术语）；语法以 `<root>/docs/课件内容格式.md` 为准 |
| 文件名 | `<序号>-<节点id>.md`，序号 = 本节点在 `curriculum.yaml` 的 `nodes:` 里排第几（4 位补零，如 `0003`）、节点 id 原样照抄——上一课的「下节课」指针按这条规则预写，名字错一位那根指针就断。**归属（这课是哪个节点、挂主页路线图哪个位置）只认文件名**：页头的 eyebrow 是给学生看的可读文字（`0001 · 第一份能提交的代码`），写不写节点 id 都不影响归属 |
| 上/下节课指针 | 不归你写：渲染器按 `curriculum.yaml` 的 `nodes:` 顺序算（第一课没有上一个、最后一课没有下一个） |
| 顶栏与主题开关 | 不归你写：顶栏、主题开关、脚本引用由渲染器产出；内容文件里出现块级 HTML 标签会被渲染器拦下 |
| 交付形态 | 内容文件 + 出题人的题库，渲染出的页面自包含（相对路径引用共享层与科目组件），浏览器直开可用、适合反复回看 |
| 配图 | 从 `<subject_path>/assets/img/pool/` 挑（索引是它的兄弟 `<subject_path>/assets/img/pool.md`，唯一检索入口）；**别依赖外链**——页面里的图要能离线打开；单张 ≤200 KB |

## 五、行文禁忌

1. 避免使用「肯定-否定」句式，如「不是...而是」。不要先假定学生会往你预想错误的方向想。
2. 避免使用生硬的类比与比喻，很多修辞你以为给学生讲清楚了但是反而加重了学生的理解负担，如「这个定义是从麻烦里长出来的」，简单的概念甚至不需要类比
3. 避免代入用户视角写行文（如「编译落到你手上，就是一个具体动作」「这轮你带走三个结论」）以及为了方便用户理解反而加重阅读负担的描述
4. 分清楚什么是重点，非重点的内容无须写得太详细。重点不明确也会显著提高阅读负担
