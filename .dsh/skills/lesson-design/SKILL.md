# 课件设计规范

课件的**唯一约束来源**。分两类：**要素** 与**倾向**（弱约束，可被覆盖）。

**这一节管的是结果，不是版式**：怎么分节、小节标题写什么、要不要小节标题、例子与代码块放哪，都由讲解角色按内容与学生偏好决定；规范不规定页面形式，学生偏好（`MEMORY.md`）优先。

**这一节也不管题目**：题面、答案、算过标准、lab 实操题全由 `practice-evaluator` 按 `layered-practice` 出；讲解角色只决定这些块插在正文哪里、怎么引入（位置与行文）。

# 一、要素（学生该拿到的结果）

1. **真实场景开场**：学生读完知道这一课解决的是什么真实麻烦、什么场景下用得上，而不是先记定义。
2. **术语先来历、后定义**：术语第一次出现时，学生先知道它为什么被发明、解决了什么，再看到定义；中英对照。
3. **权威教材的深度**：讲透前提、推导、边界与反例，不做速成课；内容长没关系，简洁不等于浅。
4. **动手一次**：
   - **实操课**（该节点挂了项目里程碑）→ 引导式实操：任务与断言由 `practice-evaluator` 出，落在 `lab/`；课件里对应一个动手块（内容由出题人给，位置与引入由你定）。
   - **概念课**（没挂里程碑）→ 轻量跟做：敲一条命令、改一行看变化、在输出里指出某个东西。不落 lab、不算交付物。分步、每步立刻能看到结果。
   - 动手块与跟做步骤的标题**按内容写中文阶段名**（如"第 3 步 · 改造"）；**不要用 L1-L4 标步骤**——L1-L4 是题目的层级词汇（见 `layered-practice` 第一节），不是页面标签。

# 二、讲法倾向（弱约束，可被覆盖）

问题感 — 先让学生感到"这是个什么麻烦"；具体先行 — 例子在定义前面；小步 — 一次给一点；学生的语言 — 沿用他自己的说法；参与 — 留出预测、改一行、复述的空间；连回项目 — 把知识与他在做的事接上。

**覆盖关系**：以上都是默认值，学生的明确要求、科目性质、任务紧急度可覆盖；`MEMORY.md` 的个人偏好优先级最高。学生反馈只经总控转达（改课件见 learning-coach），本规范不写现场应对。

# 三、实操（lab）

`lab/` 是 `practice-evaluator` 的产出物，结构与工程要求（分步引导、教程带结果、任务留白、自检可跑、答案与成品分开、`lab/NN-主题/` 与课件编号对齐、`solutions/`、`lab/README.md` 写环境与依赖）见 `layered-practice` 第六节。**本规范不管 lab**；讲解角色的活是让课件与它接上（比如课件里那个动手块指向它）。

# 四、记忆与难度（弱约束）

分清**流畅度**（当场会复述）与**存储强度**（过段时间还记得住，目标）；用**合意困难**设计：检索练习（回忆而非重读）、间隔（分散到多次会话）、交错（技能练习混合相关主题）；难度落点始终在最近发展区。

# 五、贯穿线索

每课连回三条：**最终目标**（这段知识与 `MISSION.md` 什么关系）；**配套项目**（从早期就作为实操素材逐课埋线，项目由总控盘问时定）；**工具对照**（编程类：亲手实现与现成库结果对照）。

# 六、复用与骨架（硬约束）

先读 `<subject_path>/assets/` 组件库；从 `<root>/templates/lesson.html` 拷起（顶栏、主题开关、提问提示、脚本引用已就位），**别删主题开关**；编号递增 `NNNN-dash-case.html`；新组件写进 `assets/` 不内联；自包含 HTML（相对路径引用共享层与科目组件），浏览器直开可用；排版干净、适合反复回看。

题目块的**数据字段**以 `templates/assets/quiz.js` 顶部注释为准（选择题与开放题各写什么键都在那里）；骨架注释里给了可用的块与摆放示例。嵌题时照抄出题人给的题面与答案，不改内容——要改先回去找它。
