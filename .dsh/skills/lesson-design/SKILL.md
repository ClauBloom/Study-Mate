# 课件设计规范

课件的**唯一约束来源**，分**要素**与**倾向**（弱约束，可被覆盖）两类。

**它管结果，不管版式**：怎么分节、标题写什么、例子与代码块放哪，都由讲解角色按内容与学生偏好决定；`MEMORY.md` 的个人偏好优先。题目、lab、实验说明页都不归它管（规范见 `layered-practice`）。

## 一、要素（学生该拿到的结果）

1. **真实场景开场**：读完知道这一课解决的是什么真实麻烦、什么场景下用得上，而不是先记定义
2. **术语先来历、后定义**：术语第一次出现时先知道它为什么被发明、解决了什么，再看到定义；中英对照
3. **权威教材的深度**：讲透前提、推导、边界与反例，不做速成课；简洁不等于浅
4. **动手一次**：
   - `kind: 实操` → 引导式实操：任务与断言由 `practice-evaluator` 出、落在 `lab/`；课件里对应一个动手块（内容由出题人给，位置与引入由你定）
   - `kind: 概念` → 轻量跟做：敲一条命令、改一行看变化、在输出里指出某个东西；不落 lab、不算交付物、分步且每步立刻能看到结果
   - 动手块与跟做步骤的标题按内容写中文阶段名（如"第 3 步 · 改造"），**不要用 L1-L4 标步骤**（那是题目的层级词汇）

## 二、讲法倾向（弱约束，可被覆盖）

问题感 — 先让学生感到"这是个什么麻烦"；具体先行 — 例子在定义前面；小步 — 一次给一点；学生的语言 — 沿用他自己的说法；参与 — 留出预测、改一行、复述的空间；连回项目 — 把知识与他在做的事接上。

以上都是默认值，学生的明确要求、科目性质、任务紧急度可覆盖，`MEMORY.md` 偏好优先级最高。学生反馈只经总控转达（改课件见 `learning-coach`）。

## 三、记忆与难度（弱约束）

分清**流畅度**（当场会复述）与**存储强度**（过段时间还记得住，目标）；用**合意困难**设计：检索练习（回忆而非重读）、间隔（分散到多次会话）、交错（混合相关主题）；难度落在最近发展区。

## 四、贯穿线索

每课连回三条：**最终目标**（这段知识与 `MISSION.md` 的关系）；**配套项目**（从早期就作为实操素材逐课埋线）；**工具对照**（编程类：亲手实现与现成库结果对照）。

## 五、复用与骨架（硬约束）

先读 `<subject_path>/assets/` 组件库；从 `<root>/templates/lesson.html` 拷起（顶栏、主题开关、提问提示、脚本引用已就位），**别删主题开关**；编号递增 `NNNN-dash-case.html`；新组件写进 `assets/` 不内联；自包含 HTML（相对路径引用共享层与科目组件），浏览器直开可用；排版干净、适合反复回看。

题目块的字段契约见 `templates/assets/quiz.js` 顶部注释；**嵌题时照抄出题人给的题面与答案**，要改先回去找它。

## 六、用词：三类词，三种规矩（硬约束）

1. **术语**（概念名、字段名、组件名、`GLOSSARY.md` 里确立的叫法）→ **必须一致**：同一件事在本科目里始终用同一个词，**重复出现是对的**，别为换词而换词
2. **叙述骨架**（开场怎么起、怎么把术语引出来、每节标题的句式、过渡句、收尾套话）→ **不要重复；但重复不靠换说法解决**。正要写一个和上一课一样的标题时，那是**这一课还没找到内容锚点**的信号——回去从这课特有的东西里找：学生上一课的真实表现与误解、他项目里此刻的代码与报错、上次留下的悬念、这个知识点最反直觉的那一处。**让结构从内容里长出来；换个绕弯的说法把同一套骨架再讲一遍，比重复更糟**
3. **元词**（规范与派发指令里的说法："真实场景""术语先来历""问题感""要素""倾向""埋线"）→ **不进正文**：那是写给角色的指令词。正文用词来自科目内容、学生自己的说法与 `GLOSSARY.md`
