## 一、一次学习会话长什么样

### 开场

1. 主教练读 `~/.dsh/studymate-config.yaml` 定位学习工作区，加载 `record-keeping` 并恢复状态切片（共享记忆相关分节 + 当前节点 + 前置节点摘要 + 最近 5 条误解 + 最近 3 条学习记录 + 最近 3 条评估记录）
2. 报告你上次学到哪、这次建议学什么，并把根主页的**绝对路径**写进回复（可直接点开）
3. 每一轮回复的最后一行都是「**下一步**：谁做什么 —— 怎么触发」

### 开一门新课

4. 主教练亲自盘问（这是硬流程，不是客套），必问四项：**学它的目的**（追问到具体，写进 `MISSION.md`）、**想学到什么程度**、**配套项目**（给你 3 个以上候选让你挑）、**动手用什么载体**（记进 `lab/README.md`）。记忆里已经有的信息不会再问你
5. 派课程设计角色产出大纲（知识点 DAG + 每节点的课型 `kind` + 验收点），其中会插入 3~5 个 `kind: 实验` 的验收课
6. 建科目文件夹、写进度文件、**刷新主页** —— 你从主页看到这门课的全貌

### 学一个知识点

7. 节点状态置为「学习中」，然后按课型产材料（见 §三）
8. 材料落盘后跑一次**质量闸门**（见 §五），`FAIL` 的按归属打回对应角色修，`WARN` 不阻断
9. 通过后 `present` 呈上课件 + 回复里写明绝对路径，再 `xdg-open` 帮你打开

### 学完与评估

10. 只在**评估点**派评估角色：① `kind: 实验` 的课 ② 每走完 3~5 个普通节点的一次阶段评估 ③ 你自己说「考考我」。不是评估点就用保守口径更新（读了 + 页内自测做了 + 实操断言全绿 → 状态最多到「初步理解」）
11. 通过 → 更新进度与掌握度、写评估记录与学习记录；实验课通过 → 它和它 `prerequisites` 里被验收的节点一起置「已通过项目验证」
12. 部分通过 / 不通过 → 指出具体缺口、把误解记到两个落点、安排复习

### 结束

13. 写会话摘要（`sessions/<日期>.md`，同日多段追加）+ 给一条共享记忆的更新建议（**你确认后**才写入 `MEMORY.md`）+ 刷新主页

## 二、读课件时随时提问

把看不懂的文本/代码/报错**原样贴回会话**，说一句哪里不懂就行——不需要特殊格式。

- 由主教练**亲自**回答（不为这种小问题派子 agent），先给答案再给一句为什么，控制在 200 字内
- 答完主动把你送回原位（"继续看课件吧"）
- 同时记一条误解记录，主教练上下文里只留一行摘要 —— 这就是"提问不污染主对话"的机制
- 问题超出片段范围（变成"整块知识都没懂"）→ 会明说这值得单独讲，交给学习循环安排

## 三、课型与材料（产出什么）

`curriculum.yaml` 里每个节点都有必填的 `kind`：

| `kind` | 是什么 | 产出 |
|---|---|---|
| `概念` | 只讲不落 lab（题目止于 L3） | 课件（讲解 + 轻量跟做） |
| `实操` | 学一点练一点，可到 L4 | 课件 + 自己的小 lab |
| `实验` | **里程碑验收课**：验收"学到目前的知识能做出什么" | 实验说明页（任务书）+ 验收任务 |

**每个知识点一份自包含 HTML 课件**（`lessons/<NNNN>-<节点id>.html`，`NNNN` = 节点在 `nodes:` 里的序号，一个节点一节课件）。课件里有什么：

- 真实场景开场 → 术语先讲来历再给定义 → 教材级深度（讲透前提、推导、边界、反例，不做速成课）
- 页内检索练习（选择题当场判分；开放题展开参考答案与要点标准，自评）
- 侧边目录 + 上/下节课入口（按命名规则预写指针，不用回填）
- 亮/暗主题开关长在课件自己身上

**lab（引导式实操）**：载体在开课时跟你确认，可选 notebook / 源码+测试 / 页面 / SQL / 命令行 / 练习页 / 清单。五条内核固定：分步引导 · 任务留白（亲手写）· 可验证 · 即时反馈 · 卡壳先引导不给答案。结构是 `lab/NNNN-主题/`（与课件编号同源）+ `lab/solutions/NNNN-主题/`（答案，做完再对照）+ `lab/README.md`（载体与环境、怎么跑、任务表）。

> 概念课**不该**有 lab；实操课与实验课**必须**有——这是闸门的阻断项之一。

## 四、题目：四种题型与四层

**题只有一个 owner**：`practice-evaluator`。题面、答案、算过标准、`lab/` 实操题、实验课验收任务全由它出；讲解角色只把题**原样**嵌进课件正文（位置与行文归它），主教练不出题。

| 题型 | 长什么样 | 判分 |
|---|---|---|
| 选择题 | 页内 `.quiz`，点选项即时反馈 + 一句解释 | 页内自动判 |
| 开放题 | 页内出题，**参考答案 + 要点标准点击展开**（不贴回会话） | 学生自评 |
| 实操题 | `lab/` 留白任务 + 断言 + `solutions/`，学生亲手写代码 | `npm test` 之类的自检自动判 |
| 评估题 | 评估时现场出的 1~2 题（开放） | `practice-evaluator` 判 |

数据字段的唯一出处是 `templates/assets/quiz.js` 顶部注释（选择题 `q/opts/ans/why`；开放题 `q/answer/criteria`）。

**四层**是题的层级词汇：L1 理解（判断/解释/预测输出）→ L2 改造（改一处代码看变化）→ L3 排错（定位真实 bug）→ L4 应用（放进自己的项目）。这是默认进阶路径，不是必须逐级走的台阶：项目里用过某知识点可以从高层起步，某层反复卡住可以退回来补。L1~L4 **不进页面**，只记在评估记录里。

**证据 > 口头确认**：判"会不会"看的是 ① 运行结果 ② 你自己写的测试 ③ 解释能力 ④ 口头确认（单独出现不足以判过）。节点的**验收点**（`curriculum.yaml` 的 `验收点` 字段，原字段名 `evidence`）就是过关标准，核验时逐条对。

## 五、质量闸门与脚本

主教练在打开页面前跑（阻断项：文件名与编号、**课件归属的节点在大纲里真实存在**、共享层四条与科目组件两条引用、题目结构、题目位标记残留、主题开关；`kind` 为 `实操/实验` 时还要求 lab 链接与 lab 产物齐全）：

```bash
python3 scripts/check_lesson.py <课件路径> --subject <科目目录> --node <节点id>
```

其余脚本：

```bash
python3 scripts/gen_home.py [<workspace>]        # 生成根主页 + 全部科目主页（默认读配置里的 workspace）
python3 scripts/preview_templates.py [--open]    # 用假数据渲染模板到 .preview/，只看样式与交互
python3 scripts/check_curriculum.py <curriculum.yaml> ...   # schema + 重复 id + 悬空引用 + 环 + 孤儿节点
python3 scripts/check_skill.py .dsh/skills/*     # 技能 frontmatter（改过技能就跑一次）
```

退出码约定：`check_lesson.py` / `check_curriculum.py` 有阻断项即 1；`gen_home.py` 占位符缺失或产物断链即 1。

## 六、学习数据存在哪

三个区域互不混用：**引擎项目**（本目录，源码，学习时只读）、**用户级安装**（`~/.dsh/`，预设与工作区配置）、**学习工作区**（`workspace/`，你的学习数据）。

```text
<LEARN_WORKSPACE>/
├── index.html                   # 根主页：课程总览（生成产物）
└── .learning/
    ├── MEMORY.md                # 跨科目共享记忆（我是谁 / 教学偏好 / 学习习惯 / 跨科目观察）
    ├── assets/                  # 全工作区共享的前端资源（sayo + 主题层）
    └── subjects/<slug>/         # 每门科目独立，互不读取
        ├── subject.yaml  MISSION.md  RESOURCES.md  GLOSSARY.md   # 四份元数据
        ├── curriculum.yaml      # 大纲（知识点 DAG + kind + 验收点）
        ├── progress.yaml  misconceptions.yaml
        ├── index.html           # 科目主页（生成产物）
        ├── lessons/             # HTML 课件
        ├── lab/                 # 实操 + solutions/ + README.md（概念课没有）
        ├── reference/  assets/  # 速查页 / 科目内组件
        ├── assessments/         # 评估记录
        ├── learning-records/    # 学习记录（记"真的学会了什么"）
        └── sessions/<日期>.md   # 会话摘要
```

规则要点：

- **跨科目只共享 `MEMORY.md`**，科目文件之间不互相引用
- **学习记录**只在出现可观察证据时写（正确用出概念、主动说明已知、误解被纠正）；覆盖了但没证据的不记，纯进度日志不记
- **误解记两处**：`misconceptions.yaml`（追加日志）+ `progress.yaml.misconceptions`
- **主页是生成产物**，永远别手改；状态一变就跑 `gen_home.py` 重新生成
- 换机器：整个项目（含 `workspace/`）拷走 + 跑一次 `./install.sh`

## 七、谁负责什么（9 个技能）

会话只用 StudyMate 自己的技能（预设设了 `includeDefaultRoots: false`，不读 `~/.dsh/skills/` 里你装的其他技能）。

| 角色 | 职责 |
|---|---|
| `learning-system`（总控 / 主教练） | 调度中枢：开场、盘问、学习循环、档案维护；**唯一跟你对话的人** |
| `curriculum-designer` | 课程设计：大纲与实验课节点、知识依赖、资源清单 |
| `learning-coach` | 讲解：课件正文（两回合制），不出题、不产 lab |
| `practice-evaluator` | 题目唯一 owner：出题、批改、证据核验；它不写文件，内容交总控落盘 |

规范类协议（按需加载）：`lesson-design`（课件唯一约束来源）、`layered-practice`（题目唯一规范）、`evidence-check`（证据核验口径）、`local-qa`（局部提问怎么答）、`record-keeping`（状态读写规则）。

**只派三类活**：拟大纲与实验课、做课件（两回合）、出题与评估（两个时机）。答疑、盘问、使命确认、四份元数据、全部档案记录 —— 信息源在主教练上下文里，它自己干。派出去的活不过闸门就带证据打回**同一个** agent 重做，不代改。

## 八、常见问题

<details>
<summary><b>为什么课件里会短暂出现 <code>&lt;!-- 题目位：… --&gt;</code> 标记？</b></summary>

课件是三步产出的：讲解角色先写正文并标出"题放哪"（回合一），题目角色再出题，讲解角色回合二把题**原样**嵌进去并清掉标记。带标记的中间态过不了闸门（标记残留是阻断项），所以只在生成过程中短暂存在。
</details>

<details>
<summary><b>改了 <code>templates/assets/</code> 里的组件，为什么有的页面没变？</b></summary>

共享资源有两份：`templates/assets/`（源）和各科目 `assets/`（建课时拷的副本）。`style.css`、`quiz.js`、`lesson-toc.js` 一改，要把各科目的同名副本一起覆盖（科目自己新增的组件别动）；`sayo/` 与主题层是共享层，由生成器负责。
</details>

<details>
<summary><b>大纲里插了/删了节点，指针为什么会错？</b></summary>

课件的上/下节课指针按「节点在 `nodes:` 里的序号」预写，所以节点顺序一变，旧指针可能指错。闸门会报出来，人工改一次指针即可。另外"一个节点只能一节课"是当前的设计约束。
</details>

<details>
<summary><b>离线能用吗？</b></summary>

学习数据、课件、主页全是本地文件，打开即用（无网络字体、无 CDN 依赖）。只有需要核对易变内容/查一手资料时才联网。
</details>

<details>
<summary><b>手改 YAML 时要注意什么？</b></summary>

列表项以 `&` 或 `*` 开头**必须加引号**：`["& 取地址", "* 解引用"]` —— 裸写会被当成 YAML 锚点/别名，block 与 flow 列表都会解析失败（C++ 科目踩过这个坑）。另外：写前先读、增量修改，不要整文件覆盖；任何字段都别写 `null`（没有内容就写「无」或省略可选行）；改完跑一次 `check_curriculum.py`。
</details>
