# 亮暗主题问题汇总（handoff）

> 审计日期：2026-09-18 ｜ 审计对象：StudyMate 全部页面与组件
> 触发问题：「选择题 hover 的绿色在亮色很好看，在暗色很难看」
> 审计结论：**问题不是"漏了某个主题"**（逐元素比对后，三页里唯一不随主题变色的是根 `<html>`，属正常），
> 而是**两套强调色在暗色下分裂** + 若干"只对单主题成立"的硬编码。

---

## 一、先读懂机制（不复述会白改）

### 1.1 主题切换怎么工作

| 文件 | 作用 |
|---|---|
| `assets/sayo/sayo.css` 的 `:root` | **上游 Primer 暗色**为默认值（`--syo-bg-base:#0d1117`、`--syo-accent: var(--syo-purple)`）|
| `assets/learn-theme.css` 的 `:root` | 学习语义色的**暗色**值（`--learn-*` 默认住在这里）|
| `assets/learn-theme.css` 的 `html[data-theme="light"]` | **亮色全覆盖**：把 `--syo-*` 映射成暖纸白 + 深绿，并把 `--learn-*` 换成暖色版 |
| `assets/learn-theme.js` | 切主题：`LearnTheme.apply()` / `.toggle()` / `.wire(checkbox)`；优先级 `?theme=` > localStorage > 系统 |

**一句话：暗色是保底默认，亮色是覆盖层。** 所以"忘记适配暗色"的典型形态是——
在**无主题前缀**的规则里写死一个"亮色才成立"的值（深色阴影、近白色底、暖绿），
它会**同时生效于两个主题**，暗色下就露馅。

### 1.2 最根本的一处不对称：强调色在两个主题下不是同一个色相

| 令牌 | 暗色 | 亮色 | 色相 |
|---|---|---|---|
| `--syo-accent` | `#bc8cff`（Primer 紫） | `#2f7d5f`（学习深绿） | **265° vs 157°** |
| `--syo-green` | `#3fb950` | `#2f7d5f` | 绿 / 绿 |
| `--learn-soft-accent` | `rgba(188,140,255,.12)` **紫** | `rgba(47,125,95,.10)` 绿 | **紫 vs 绿** |

- 边框、链接、聚焦环、`.doc-sidebar a.active` 等用的是 `--syo-accent` → **暗色紫、亮色绿**。
- 但 `.lesson-goal`、`.quiz__opt` 等**观感强调**用的是 `--learn-soft-*` → **两个主题都是暖绿**。

**结果：暗色页面里"边框是紫的、强调块是绿的"，两种强调色同时出现。** 这就是「说不上哪丑」的来源。
见 §2.1、§2.2。

## 二、问题清单

> 每条给：位置 / 表现 / 为什么 / 建议改法。**建议改法只为指明方向，具体取值由接手的人定。**

### P1 · 选择题 hover 底色与强调色打架（用户原始反馈）

- **位置**：`templates/assets/style.css` 与 `workspace/.learning/subjects/cpp-algorithms/assets/style.css`
  ```css
  .quiz__opt:hover { border-color: var(--syo-accent); color: var(--syo-fg-default); background: var(--learn-soft-green); }
  ```
- **表现**：亮色下好看（绿边框 + 绿底 = 同色系）；暗色下**紫边框 + 绿底**，底色调向脏绿（合成值 `#13251e`），观感浑浊。
- **实测**：暗色 hover 底 `#13251e`，文字对比度 10.38:1、边框 6.36:1 —— **对比度都达标，纯粹是色彩语义打架**（边框 265° / 底 157°，差 108°）。
- **建议**：
  - 方案 A（推荐，改动最小）：hover 底不用语义色，改用**中性提升**，例如 `background: color-mix(in srgb, var(--syo-bg-base) 88%, var(--syo-fg-default))`，让"可点"由边框 + 轻微变亮表达。
  - 方案 B：把 hover 底也绑到 `--syo-accent` 的柔和版（`--learn-soft-accent` 是紫的，与边框同色系）——但注意 `--learn-soft-accent` 在亮色是绿，正好也对。
  - ⚠️ 不要只改暗色：`.quiz__opt:hover` 也会命中 `.quiz__reveal`（「想好了，看参考答案」按钮）与任何放在 `.quiz` 里的按钮。

### P2 · `.lesson-goal` 与暗色强调色分裂（同类，但更容易被忽略）

> **复核结论：本条不成立**（2026-09-18 晚实测，见 §七）——暗色下 `--learn-soft-accent` 是
> `rgba(188,140,255,.12)`，与暗色强调色同为紫，`.lesson-goal` 在两个主题里都与各自强调色同源。
> 保留原文以便对照。

- **位置**：`assets/style.css` → `.lesson-goal { background: var(--learn-soft-accent); }`
- **表现**：暗色下这一块是**暗绿**，而同一页的边框/链接是**紫**。整页出现两套强调色。
- **建议**：决定"强调色语义归谁"——要么让 `--learn-soft-accent` 在暗色也走紫（即 `rgba(188,140,255,.12)`，与 `--syo-accent` 同源），要么把 `.lesson-goal` 改用中性面（`--syo-bg-surface` + 左侧强调条）。
  **这是全局决策，改一处会影响 `.learn-*` 的所有使用者。**

### P3 · `.quiz__opt` 等按钮在暗色下缺"被选中/已答"的视觉残留

> **复核结论：本条不成立**（2026-09-18 晚实测，见 §七）——`quiz.js` 在**同一次点击**里就给被选项
> 同时加上 `.is-picked` + `.is-correct`（或 `.is-wrong`），后两者的 CSS 会换底色，所以"选了哪项"
> 一直是有底色 + 边框 + 反馈文字三重信号的；单独看 `.is-picked` 确实只有边框，但它从不单独出现。
> 保留原文以便对照。

- **位置**：`assets/style.css` → `.quiz__opt.is-picked { border-color: var(--syo-accent); }`；`quiz.js` 只加该类，不换底色。
- **表现**：学生答完第一题、滚到第二题时，**看不出第一题选的哪项**（只有边框色差）。亮色下边框绿较显眼，暗色下紫色边框在暗底上更弱。
- **建议**：给 `.is-picked` 加一个底色（同样建议中性化，见 P1），或加左侧 3px 强调条 + 打勾图标（不依赖颜色）。

### P4 · `.quiz` 卡片阴影在暗色下不可见（**本次审计期间新引入**）

- **位置**：`assets/style.css` → `.quiz { box-shadow: 0 1px 2px rgba(38, 36, 31, .05), 0 6px 16px rgba(38, 36, 31, .05); }`
- **表现**：亮色下卡片靠阴影立起形状（页面底 `#f7f5f0` 与卡片底 `#ffffff` 只差 1.09:1，没阴影就分不出边界）；暗色下阴影是深色叠深底，**等于没有**，卡片又变回"无边无形"。
- **对照**：`learn-theme.css` 里所有阴影都写在 `html[data-theme="light"]` 下（§4「亮色下修正 Sayo 为暗色硬编码的阴影与光晕」），暗色沿用 Sayo 自己的处理。**本项目没有全局阴影令牌。**
- **建议**：把阴影提成令牌（例如 `--learn-shadow-card`，暗色下用更低的透明度 + 一圈 `--syo-border` 描边代替），或把 `.quiz` 的阴影同样只在 `html[data-theme="light"]` 下声明、暗色靠 `--syo-border` 区分。

### P5 · 侧边目录「当前小节」硬编码紫色（**亮色下失效**，与 P1 方向相反）

- **位置**：`assets/style.css` → `.doc-sidebar a.active { color: var(--syo-accent); background: rgba(188, 140, 255, 0.08); border-left-color: var(--syo-accent); }`
- **表现**：`rgba(188,140,255,.08)` 是 Primer 紫，只在**暗色**成立；亮色下强调色是绿，于是"文字/左边条是绿、底色是极淡的紫"，亮色下这块底色几乎不可见（白底叠 8% 紫）。
- **建议**：换成 `var(--learn-soft-accent)`（两主题各自成立），或 `color-mix(in srgb, var(--syo-accent) 8%, transparent)`。

### P6 · 亮色下有 34 处文本对比度不达标（**暗色 0 处**）

- **位置**：课件页；`assets/style.css` 的语法高亮、行内 `code`、`.lesson-tip` 标签。
- 34 处是重复计数，**去重后只有 4 类**：

| 出现 | 对比度 | 元素 | 字号 | 前景 | 背景 |
|---|---|---|---|---|---|
| ×20 | **3.72** | 代码注释 `span`（含 `.syn-comment` 9 处） | 12.2px | `rgb(138,132,120)` | `rgb(255,255,255)` |
| ×9 | **3.72** | 同上（`.syn-comment` 类名形态，与上一行是同一处规则） | 12.2px | `rgb(138,132,120)` | `rgb(255,255,255)` |

- **位置**：`assets/style.css` → `.sidebar-backdrop { background: rgba(0,0,0,0.5); }`、`.doc-sidebar { box-shadow: 2px 0 16px rgba(0,0,0,0.3); }`

## 三、审计方法（接手的人可以复跑）

1. **列颜色字面量**：扫描非令牌定义块里的 `#hex` / `rgb()` / `hsl()` / 命名色。
   令牌定义块（`:root`、`html[data-theme="…"]`）内的字面量是合法的，要排除。
2. **逐元素跨主题比对**：同页渲染两次（`?theme=light` / `?theme=dark`），
   收集每个可见元素的 `color` / `backgroundColor` / `borderTopColor`，**找出两主题下完全相同的元素**
   ——那必然意味着没走令牌。本次结果是"仅根 `<html>`"，说明接线本身是通的。
3. **逐元素算对比度**：把元素背景逐层向上合成（处理 alpha），再算 WCAG 对比度，按字号取阈值。
4. ⚠️ **两个坑**（我踩过）：
   - `file://` 下 `document.styleSheets[i].cssRules` 会被安全策略挡住，**读不到不等于规则不存在**。
   - `--headless` 截图会命中 `file://` 的 CSS 缓存，改完 CSS 看不到变化时先怀疑缓存（用内联 CSS 或独立 profile 绕开）。
   - 主题不能靠截图肉眼辨认（`LearnTheme` 会按 localStorage 覆盖）：要在样式生效前写 `data-theme`，或程序化读计算值。

## 五、改动落盘须知（重要）

**所有共享资源都有两份，改一份等于没改：**

```
templates/assets/{style.css, learn-theme.css, quiz.js, lesson-toc.js}   ← 模板（新生效）
workspace/.learning/assets/{learn-theme.css, sayo/, ...}                ← 工作区共享层（学生实际加载）
workspace/.learning/subjects/<slug>/assets/{style.css, quiz.js, lesson-toc.js}  ← 科目组件副本
```

- `templates/` 是源头，`workspace/` 是运行副本；**两份不一致会导致"改了没效果"**。
- 科目组件副本按科目各存一份（换科目要重新拷贝）。
- 改完跑 `python3 scripts/check_lesson.py <课件> --subject <科目> --node <节点>` 确认闸门仍 `OK`。

### 7.4 顺手修的扫描器 bug

`scan()` 用 `text.find(line)` 反查行偏移——**内容完全相同的行**（CSS 里很常见）会一律解析到第一次出现的位置，
于是第二次起即使不在令牌块内也会被误判成"块内"而**静默漏报**。已改为逐行累加偏移量，并加了三个 fixture
（重复行 / 唯一行 / 纯令牌块）验证：修前 `dup.css` 漏报 1 处，修后 3/3 通过。真实文件复跑结果不变
（说明这份审计的清单本身没被这个 bug 影响）。
