### 1. `templates/assets/quiz.js` 契约的转义规则有一条**错的**（`" → &quot;`）

**状态：仍待修，而且 `4bd476a` 把它"修"反了。**

**它做了什么**：那个 commit 在 `quiz.js` 顶部**新增**了一整段"属性值的引号（必读）"规则块——
内容是 `' → &#39;`、`" → &quot;`、`< → &lt;`、`> → &gt;`，还附了可抄的样例，并同步到三份副本
（模板 / workspace 科目 / examples 科目）。

**为什么这没修好**：

1. **我最初的报告标题误导了它**。我写的是"契约**缺**转义规则"，后来才更正为"规则里
   **有一条是错的**"。它照"缺"来补 → 把错的那条复制成了正式规则。
2. **它的验证没盖到出问题的那一半**。commit message 里的验证是"裸 `'` 写法 FAIL／实体写法 OK"，
   并说"headless Chrome 实测：实体写法题干渲染为 `expected ';' before 'return'`"——
   **那测的是单引号，而 `&#39;` 恰好是对的**。`"` → `&quot;` 从头到尾没被测过。
3. **缺陷因此升级**：四份已完工课件原本因为没照旧规则写而侥幸没坏（`&quot;` 计数全 0）；
   现在契约给了可抄样例，**下一个照抄的课件就会在学生的浏览器里退化成「题目数据解析失败」**。

**契约现在写的是**（`templates/assets/quiz.js` 顶部）：

```
属性值的引号（**必读**；写错闸门会拦，浏览器里题目块直接退化成「题目数据解析失败」）：
 属性值里出现**同种**引号是 HTML5 禁止的，浏览器必然在那里把属性截断。所以值里的
 引号一律写成实体——浏览器解码后再交给 JS，拿到的仍是原文：

   单引号 ' → &#39;     双引号 " → &quot;     小于号 < → &lt;     大于号 > → &gt;
```

**`' → &#39;` 是对的；`" → &quot;` 是错的。** 差别在于：`&#39;` 解码成裸 `'` 放进
**JSON 字符串内部**是合法的；而 `&quot;` 解码成裸 `"` 放进 JSON 字符串内部**非法**，
会提前闭合字符串。

**为什么「浏览器解码后再交给 JS，拿到的仍是原文」这句会误导**：解码这一步对两种引号确实一样
（`&#39;`/`&quot;` 在属性里都会被解码回裸字符，真实浏览器对照实验已证），但它没往下想一步——
**解码后的文本要过 `JSON.parse`，而 JSON 里字符串的分隔符就是 `"`**。裸 `"` 会截断。

**实测（真实 headless Chrome + `JSON.parse`，2026-09-18 复核）**：

| 属性里写 | 浏览器解码后 | 结果 |
|---|---|---|
| `data-quiz='[{"q":"printf(&quot;x&quot;)"}]'` | → `printf("x")` | **JSONDecodeError: Expecting ',' delimiter** |
| `data-quiz='[{"q":"printf(\"x\")"}]'` | 原样 | ✅ 解析成功 → `printf("x")` |

**两个附带事实（都实测过）**：

1. **闸门拦不住这条错**：`check_lesson.py` 的 `check_quiz_attr_delimiters()` 只查"裸的**同种**引号"
   （属性用单引号 → 只查裸 `'`），所以照契约写成 `&quot;` 的课件**闸门放行、浏览器里炸**。
2. **已有课件全都没照契约做**：四份课件 `&quot;` 均为 **0 处**，含 `printf`/`cout` 的题一律用
   裸 `"`（JSON 合法写法）或 `\"`（`0003` 18 处、`0004` 10 处）。

**修法**：按属性用什么引号包裹**分开写**（下表），并补一句"解码后的文本要过 `JSON.parse`，
而 JSON 字符串的分隔符是 `"`"：

| 属性写法 | 值里出现 `'` | 值里出现 `"` |
|---|---|---|
| `data-quiz='…'`（**单引号包裹**，本项目的实际写法） | 写 `&#39;`（**必须**——裸 `'` 会截断属性） | **不要写 `&quot;`**！保留 JSON 自己的 `\"` 即可 |
| `data-quiz="…"`（双引号包裹） | 写 `&#39;` | 写 `&quot;`（裸 `"` 会截断属性） |

`<` / `>` 一律 `&lt;` / `&gt;`（两种包裹方式都一样，裸 `<`/`>` 在属性值里都非法）；`&` 写 `&amp;`。

**顺带建议（可选加固）**：给 `check_quiz_attr_delimiters()` 加一条「**单引号包裹的属性值里出现
`&quot;` 即 FAIL**」——这个写法在单引号属性里**一定是错的**，可无歧义地拦；那样即便契约又被写错，
闸门也能兜住。

**注**：这条**不是**本轮或"修规范那个会话"新引入的——`git show HEAD:templates/assets/quiz.js`
可证它是**基线原有**的设计；`4bd476a` 只是把它从"没人照做"变成了"正式规则"。

`layered-practice` 第三节要求「题面、参考答案、要点标准的单行控制在 40 字以内」，但**排错题（L3）必然要贴代码**——函数签名、`return` 行、靠空格对齐的注释天然超 40 字。本轮第 4 课就撞上了：出题人交了 7 行超限，**全部是代码**（散文行最长才 24 字）。

**当时的现场裁决**（总控给的，供改规范时参照）：

| 内容类型 | 上限 |
|---|---|
| 纯散文行（题干、设问、说明） | **≤40 字**（不变） |
| 代码块里的代码行 | **≤60 字**（显示宽度） |
| 靠空格对齐的注释列 | 必须**拆开**（不靠对齐阅读） |
| 代码块 | 必须独立成段、与叙述之间空行 |

**现状（2026-09-18 复核）：`layered-practice:44` 仍是笼统一句「单行控制在 40 字以内」，未区分。** 这条**仍待修**，裁决表见本节上方，可直接抄。

**实测支持**：本轮第 5 课有一行 42 字（8 空格缩进 + `if (x > 0.0) printf("扣款 %g\n", x);`）——若按"散文 ≤40"判它是超限，按"代码 ≤60"判则合规。**不区分会让合规的排错题被当成缺陷反复退回。**

## 七、提示词层面新发现的问题（2026-09-18 晚，第 4–5 课批量备课暴露）

> **状态**：7.1 与 7.2 的**核心要求已被派发规范吸收**（见下），但还有两条缺口没写进去；7.3、7.4、7.5、7.6 **仍待处理**。

> 这一节是**这轮真实踩出来的**，不是推测。前 5 条我都标注了"如果没兜住会怎样"，因为它们都属于**肉眼看不出来**的类型。

### 7.1 题目位与出题人的分组之间没有共同标识 —— **已造成实际错位**

**事实**：我给 `practice-evaluator` 的输入是课件里 5 处题目位的**文字清单**（含行号与内容描述）。它按自己的出题逻辑组织成了 5 组切片，**但切片编号顺序 ≠ 题目位的物理顺序**。我在派嵌题时按"第 N 片 → 第 N 位"顺次对位，**错了 2 处**；而且它判断其中一处（`while + continue`）**不值得出题**，所以**题目数量与题目位数量也不相等**。

**兜住它的是一次"动手前自检"**：`learning-coach` 在嵌之前核对了每片的内容与注释的题型形状，发现 `positions/05.json` 是"1 选择 + 1 开放"、与它被我指到的那一处（2 选择）不符，于是停下报告。**如果它照我的表直接贴，两组题会落在不匹配的小节里，而且肉眼极难发现**——题目本身都是好题，只是位置错了。

**修法**（`learning-system` 的派发规范现在只写了"上游产出原样携带"，**下面 4 条里 1、2 还没写进去**）：

1. **每一片附带"内容锚点"**（该片首题首行的文字、或一个标志串），例如「含 `printf("扣款 %g\n", x)` 的那片 → 悬垂 else 那一位」——**还没写进规范**；
2. **要求角色按锚点自检对位并在返回里报告**（给出它是靠哪个特征串确认的）——**还没写进规范**（这次是角色自己想到要做的，不是规范要求的）；
3. **派活前先核"每个题目位是否都有片"**——题目数量不必等于题目位数量，缺口要显式说明怎么处理（挂相邻题收紧、或删掉该位的注释）；
4. 出题人侧同步一条：**切片顺序应与页面顺序一致**，或在 `manifest` 里给出"片 ↔ 位"映射（第 3 课那次给了 `manifest.json`，第 5 课这次没给，我靠猜就错了）。

### 7.2 出题人切片的编号顺序与页面顺序不一致（同上一条的根因）

建议在 `layered-practice` 第六节明写：「切片编号**必须**与页面物理顺序一致；若因题型互换而无法一致（如 L306/L333 那种），**必须在 manifest 里给映射表**」。

### 7.3 多轮迭代之间交换的"文件清单 + md5"没有既定格式

**事实**：我这轮**两三次凭记忆写 md5 基准**，每次都发出一条纠正消息（"我给的 md5 是占位值、这是真值"）。基准值这种东西不该靠记忆——它一旦错，正确执行的角色会被"校验失败"拦住（本轮讲解角色就差点被我要求"不一致就停下"）。

**修法**：规范里给一个固定格式，总控派工时**必须现场算**（`md5sum <file> | cut -c1-12`）并原样贴；角色的返回里也必须带同一格式。

### 7.4 产出接口"文件叫什么、在哪"没写死 —— **让学生拿到编不过的参考解**

**事实（第 3 课 lab）**：节点的 `practice` 要求"快读快写模板"，`run_tests.sh` 找的是 `fast.cpp`；出题人把参考解写成 `main_fast.cpp` 且 `#include "fastio.template.h"`——**那个头文件只在 `solutions/` 里**，学生照 README 拷成 `fast.cpp` 后必 CE（实测 `fatal error: fastio.template.h: 没有那个文件或目录`）。

**这是"两个角色的产出要对接、但接口没定义"的典型**：出题人以为模板是共享的，学生的工作区里却没有它。

**修法**：`layered-practice` 第六节补一条硬要求——**`solutions/` 里的参考解必须自包含**（学生把它拷到自己目录后能直接编译）；需要单独入库的模板（如 `myfastio.h`）**另存一份**并在 README 里说明两者分工。

### 7.5 出题人与嵌题方对"转义"的责任边界没说清

**事实**：`quiz.js` 契约那条错的 `" → &quot;` 之外，还有一层**责任边界**问题——出题人交的是 JSON（内部用 `\"`），嵌题方负责 HTML 实体化。但"哪些字符要实体化、哪些**不能**实体化"没有一份权威清单，两边都靠我口头传。本轮我传的口径被两个角色分别用实测验证过（它们都复现了 `&quot;` 会截断），但**这是我临时给的，不是规范**。

**修法**：见第一节——把对照表写进 `quiz.js` 契约，并按"属性用什么引号包裹"分开写。

### 7.6 `learning-coach` 与 `layered-practice` 对"题目位"的说法不一致

`learning-coach` 的指令里有"题目位：动手块（实操课，指向 `lab/NNNN-…`）"，而 `layered-practice` 说"`▸ 你的任务` 只是常见写法，不是必须"。**题目位该不该覆盖每个动手段落、用什么标识、数量该几处**——两处没有对齐的口径，这正是 7.1 错位能发生的前提。

**修法**：在 `layered-practice`（题目的唯一规范）里给出"题目位"的正式定义：数量建议、标识写法、以及**动手段落是否算一个位**（本轮一位是动手块、无题，出题人用 `[]` + `empty_reason` 标记，这个做法值得写进规范）。

## 八、方法教训（给后续的总控，不是规范问题）

这两条是这轮**我自己犯的**，但下一个会话很可能重犯：

### 8.1 分清"这是我的改动"还是"基线本来如此"

这轮我有**两次没先读实现就下结论**，而且两次的后果不同（值得分开记）：

1. **页头归属那次是完全报错了**——我把它当缺陷报出去、还改了代码，实际是既有设计（真正原因是文件名正则不容许点号，两个 bug 叠在一起，我修了错的那个）；
2. **契约转义那次现象是真的，但我把标题写错了**——我写的是"契约**缺**转义规则"，实际是"规则里**有一条是错的**"。后果比报错更糟：接手会话照"缺"去补，**把错的那条复制成了正式规则**（见第一节）。

**教训的准确表述**：报缺陷时，**先把"现状是什么"写准**（是缺？是错？还是我理解错了？），再写建议。标题里一个字的不同，会让下游做出完全不同的修改。
**手段很简单**：`git show HEAD:<file> | grep <关键行>` 对比一下，或者看 `git status` 里该文件是否在修改清单里。**基线里就有的东西，先假设它是故意的**，再去找为什么。

### 8.2 规范写的和代码做的不一致时，先信代码 + 实测

四份课件的 `&quot;` 计数都是 0——**它们恰恰因为没照那条错规则写，才一直没出事**。反过来，如果哪个角色老实照规范写，课件在浏览器里就坏了。**"没人按它做"本身就是一个信号**：要么规则错，要么规则已过时。
