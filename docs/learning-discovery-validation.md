下表的“走读通过”表示按提示词与调用边界逐步检查过，并不等于已在目标 DSH 模型中运行完整对话。所有行的目标模型对话验证仍待进行。

独立代理做过一次隔离的模型响应采样：提供已发生八问的虚拟上下文，学生对游戏和小装置有兴趣、零基础、时间与设备仍未知，再回复“我还是不确定”。模型下一条回复停止追问，给游戏与小装置两个暂定候选、基础建议、条件路径、未知项及选择菜单。它没有运行真实 DSH 学习模式；只采样一条回复，也没有验证完整多轮计数、角色工具调用或运行时写入。不得将此样本当作所有场景通过。

## 确认前无写入：复核范围

已人工检查入口先于首次 `MEMORY.md` 写入，探索与开课准备有独立收尾边界，不套用正式科目的摘要 schema。新协议不生成 subject、node、assessment、题库或课程 DAG，记忆、进度、掌握度和主页都不由探索修改。交接保留目的、深度、基础来源、时间设备、偏好、项目载体与未知项；总控在确认后映射到 `subject.yaml` 与 `MISSION.md` 原分节，再传已确认摘要给课程设计。

本次开发与检查没有在源码根创建真实 `.learning/` 或 `workspace/`，示例学习数据无差异；回归产生的学习文件来自临时测试 fixture。这个文件检查不能代替真实探索的无写入验证。

后续在隔离的学习工作区运行上述对话时，应在各场景前后比较学习目录的文件清单与内容摘要，并保存模型回复及工具调用记录：确认前须无新科目、无记忆／进度／掌握度变更；退出也不能创建科目摘要。尤其需实测第八问后、跳过探索后和选中候选但未确认建课时的边界。运行真实课程生成与首课渲染的端到端流程仍待验证；本次未改页面，不运行浏览器视觉套件。
