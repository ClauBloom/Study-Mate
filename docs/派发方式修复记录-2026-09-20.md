## 二、根因：fork 播的是"总控已完成的回合"

- fork 的语义是"用**已完成的回合**播种子 agent"。21:51:19 派发时，回合 1（21:33:57–21:49:38）
  已完成，而那一段**正是建科目**：子会话文件里躺着总控 21:37:13 写 `subject.yaml`／`MISSION.md`、
  21:39:43 写 `progress.yaml`／`misconceptions.yaml` 的动作，之后才接上 21:51:19 的角色 prompt。
- **反证**：同样用 fork 派的 `resource-scout`(`da5afaf7`) 表现完全正确——它在 21:37:05 派出，
  当时**一个回合都还没完成**，种子是空的。⇒ 污染源是种子里的总控历史，不是角色 prompt 写得不好。
- 后果：两个角色都以为自己就是总控，于是去写元数据、装环境、**再派一遍角色**。

## 四、改动

### 1. 预设（结构性，`preset/learning/agent.cordis.yml`）

- `tool-subagent-fork` 行加 `disabled: true`——学习模式里干脆不存在 fork 工具（写法照同文件里
  codex/claude-code 两行的 `disabled`）。
- `tool-subagent` 行加 `maxDepth: 1`（默认 3）——总控 depth 0 → 角色 depth 1；**角色再派 agent
  会在启动时被拒**（工具仍可见，调用返回出错的工具结果）。

### 2. 提示词（`.dsh/skills/`）

- `learning-system` §子 agent 派发规范 +4 条：派角色**只用全新上下文的 `subagent`**（含 fork
  为什么坏的实测记录）、角色只干活不调度（不派 agent／不用 `ask_user_question`／不建改环境）、
  同一科目同时只有一个写入者、暂存目录按角色分开且交付要报能复算的规模；另在"prompt 必须含"
  一条里加上**三条边界**，让每个角色的派工 prompt 都带边界。
- `curriculum-designer` §六加"交付时报出规模"（节点数/`kind` 分布/边数 + 校验器原文输出）；
  §边界加"不派子 agent、不调用 `ask_user_question`"与"草稿只写总控指定的暂存目录"。

### 3. 测试

- `scripts/tests/test_skill_rules.py`：提示词规则 **342 → 353**（learning-system +8、curriculum-designer +3），
  片段都按文件原文逐字取、各文件内唯一（两条一开始没对上原文，被这道闸门当场拦下后改成原文子串）。
- `scripts/tests/test_install.py`：**16 → 19 项**——装出来的预设要能整份解析成 YAML（含 `!!js` 行，
  用容忍 `tag:yaml.org,2002:js` 的加载器）、`tool-subagent-fork.disabled is True`、
  `tool-subagent.config.maxDepth == 1`。三个变异（去掉 `disabled`／改成 `maxDepth: 2`／把 YAML
  打坏）分别能把这 1、1、3 项转红——断言不是永远绿的。
- 计数标签同步：`scripts/tests/run_tests.sh:25,32`、`scripts/tests/README.md:15,22`。
