# StudyMate 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个基于 DSH 的长期自学 Agent：支持多门科目各自管理、一份跨科目共享记忆（`MEMORY.md`）、会话级"学习模式"预设 + 角色 skill + 子 agent 分发；新课程由**总控亲自**盘问（目标程度、配合项目、实操载体，子 agent 不与用户交互）；教学风格用原则性提示（弱约束），数据结构与文件职责用硬约束。主页用本地 HTML 体系（根主页 + 科目主页，模板见 `templates/`）。

**Architecture:** 主 agent 在"学习模式"预设下担任总控（learning-system skill），负责科目路由、状态读写、**一切用户交互与全部档案记录**；三个角色（课程设计、讲解、练习评估）以 skill 形式存在——它们做需要外部检索/大量生成/独立验证的活，主 agent 派发时在 prompt 中内联角色要点。**分派原则：信息源在总控上下文里的工作（答疑、盘问、记录、摘要、元数据）总控自己做；需要外部检索或大量生成的工作（拟大纲、做课件、出题评估）派角色。** **三区域分离**：引擎项目（源码）+ 用户级安装 `~/.dsh/`（预设、工作区配置）+ 学习工作区（`.learning/MEMORY.md` 跨科目共享记忆、`.learning/subjects/<科目>/` 每科目独立文件夹、根主页与科目主页）。会话可在任意目录启动：学习预设把 skill 目录指向引擎项目，学习数据由 `~/.dsh/studymate-config.yaml` 定位。主页是生成产物，由 `scripts/gen_home.py` 输出到学习工作区。

**Tech Stack:** DSH（cordis 插件体系、agent 预设、skill 机制）、YAML/JSON（结构化数据与 schema）、Markdown（skill 与共享记忆）、Python3（校验与主页生成脚本，本机已装 pyyaml）；主页用本地 HTML 文件体系（模板 `templates/home-index.html` / `subject-index.html` + 生成器，前端基座是 vendored Sayo UI）。

**Spec:** [docs/设计方案.md](./设计方案.md) — 本计划从该文档推导，执行时两份一起读。

## Global Constraints

> **题目系统 v2 已生效**：本节与 Task 2 / 3 / 4 / 5 / 7 / 8 / 9 / 12 / 13 / 14 里关于**题目归属、课型、`过关标准`（原 `evidence`）、项目里程碑、闸门判定、课件要素与讲法倾向**的描述，均已被文末 `## 题目系统重构（v2）` 与其中 §4c 覆盖——**以那些为准**。

- 项目根目录：`<root>`（即**引擎项目**；本文档里所有 `<root>/…` 都指它）
- **三个区域，互不混用**：
  - **引擎项目** `<root>/`：系统源码（skills 源、preset 源、schemas、templates、scripts、examples、docs），学习时只读
  - **用户级安装** `~/.dsh/`：`.agent-presets/learning/`（学习模式预设，里面记录引擎项目的 skill 目录）、`studymate-config.yaml`（学习工作区定位）——由 `install.sh` 写入，与会话目录无关
  - **学习工作区**：默认 `<root>/workspace/`（可经 `~/.dsh/studymate-config.yaml` 改）。所有学习数据（`.learning/`、根主页、科目主页）只放在这里
- **会话可在任意目录启动**：总控开场先读 `~/.dsh/studymate-config.yaml` 拿到工作区路径（`LEARN_WORKSPACE`），所有读写都基于该路径；不在会话 cwd 里建或找任何学习文件
- **两类文档两种写法**：
  - **教学风格类**（`lesson-design` 第二节的讲法倾向、总控答疑的做法）写**原则与倾向**，正面措辞（写"先建立问题感"，不写"禁止给定义"），并声明可被学生要求与 `MEMORY.md` 偏好覆盖；而**课件的要素**（第一节）与实操规范（第三节）是硬约束——都写在规范里
  - **结构与数据类**（文件路径、schema、角色边界、证据核验）写**硬约束**，用"必须/不允许"明确表达
- skill 源放在 `<root>/.dsh/skills/<名字>/SKILL.md`（**平级一层**：DSH 只扫一层目录找 `SKILL.md`），frontmatter 的 `name` 与目录名一致；**学习预设用 `customSkillDirs` 指向这个目录、并设 `includeDefaultRoots: false`**（`install.sh` 写入实际路径）——学习会话只加载 StudyMate 自己的技能，不背机器上已装的其他技能；也不往 `~/.dsh/skills/` 装链接，其他会话看不到 StudyMate 的技能
- **learning-system 与五个协议**允许模型直接加载（`skill` 工具按名字加载：总控加载协议；角色子 agent 也自己加载它需要的协议，例如 learning-coach 加载 `lesson-design`）；**三个角色两个调用面都关**（`disable-model-invocation: true` + `user-invocable: false`：模型目录与人类命令里都不出现，它们只是磁盘上的规格文件），由总控在派发 prompt 里内联要点（角色是"派出去的工人"，不需要出现在任何技能入口里）
- `curriculum.yaml`、`progress.yaml`、`session-summary`、`subject.yaml` 按 `schemas/*.json` 校验后才算交付
- **YAML 里的日期一律加引号**：`created_at: "2026-09-15"`。不加引号时 YAML 会解析成日期对象，schema 要求的是字符串，校验会失败（已实测）
- **skill frontmatter 用 `scripts/check_skill.py` 校验**：直接 `yaml.safe_load` 整个 `SKILL.md` 会因 frontmatter 与正文构成多文档而报 ComposerError（已实测），不要那样写
- 预设目录 `<root>/preset/learning/` 是 `~/.dsh/.agent-presets/learning/` 的源；`install.sh` 负责拷贝，禁止直接改 `~/.dsh/.agent-presets/learning/`
- 面向学生的输出一律中文；skill 内部指令用中文
- **课件规则**：所有课件约束的**唯一来源是 `lesson-design`**（要素/实操规范/讲法倾向/记忆难度/贯穿线索/复用骨架）——本节只写路径与工程硬约束。讲解以 **「HTML 课件 + 引导式实操」两件套**为载体：课件 `<LEARN_WORKSPACE>/.learning/subjects/<slug>/lessons/<NNNN>-<节点id>.html`（NNNN = 节点在 `curriculum.yaml` 的 `nodes:` 里的序号；上一课的「下节课」指针按这条规则预写，闸门拦名字与指针）、实操 `<...>/lab/01-xxx…`（编号与课件对齐；**载体由总控在盘问时与学生确定**——科目性质/熟悉技术栈/环境/偏好——写进 `lab/README.md`；讲解角色按 `lesson-design` 第三节实现），**从 `<root>/templates/lesson.html` 骨架拷起**（顶栏、主题开关、提问提示、脚本引用都已就位）（骨架只给工程外壳与组件示例，**正文的章节与版式由讲解角色自定**）；课件链接共享层（`../../../assets/sayo/sayo.css`、`../../../assets/learn-theme.css`、`../../../assets/learn-theme.js`、`../../../assets/sayo/sayo.js`）与科目内组件（`../assets/style.css`、`../assets/quiz.js`），先读复用、不内联可复用代码；每个课件包含讲解 + 交互练习（`.quiz[data-quiz]`）；**课件页自带亮/暗主题开关**（学生常由总控用 `xdg-open`/`open` 直接打开课件文件，没有主页导航可点，开关必须长在课件自己身上）
- **主页规则**：`<LEARN_WORKSPACE>/index.html` 是根主页（课程总览），`<LEARN_WORKSPACE>/.learning/subjects/<slug>/index.html` 是科目主页（大纲路线图 + 附件）；主页是**生成产物**（总控在新建科目、节点状态变化、课件新增后重新生成），数据源是 curriculum.yaml / progress.yaml / lessons/ / reference/ 等科目目录
- **前端技术选型**：Sayo UI（自研零依赖 CSS 框架 + 交互引擎，MIT，vendored 在 `templates/assets/sayo/`）作组件基座 + `templates/assets/learn-theme.css` 作共享主题层（**亮色 = 暖纸白 + 深绿**，**暗色 = Sayo 自带的 Primer 暗色**）+ `templates/assets/learn-theme.js` 作**共享行为层**：主题逻辑（`LearnTheme.apply/set/toggle/current/wire`）+ **代码块高亮**（`LearnTheme.highlight`，课件的 `<pre><code>` 与 `.syo-editor` 加载即自动上色，`data-lang` 可指定语言）；三个页面共用一份，页面里不要再各写一套。课件层 `templates/assets/style.css` 与 `templates/assets/quiz.js` 叠在 Sayo 之上。装饰性交互（自定义光标/光晕/拖尾/波纹）一律不开；只开科目页附件区的惯性滚动（主页抬头原来那套星空视差随星空层一起撤了）。根主页抬头另有一张共享图 `templates/assets/learn-mascot.png`（看板娘）与一段一次性入场动效。资源摆放与各页面引用路径见 `templates/assets/README.md`
- **模板与生成器的约定**：模板 `templates/home-index.html` / `subject-index.html` 只放骨架与样式，**数据位置用占位符 HTML 注释**（`<!-- @LEARN:XXX -->`），由 `gen_home.py` 替换——**区块级占位符必须独立成行**（按整行替换），**字段级占位符可嵌在标签内**（如 `<title><!-- @LEARN:TITLE --> · 课程主页</title>`，按值替换、出现几次换几次）；**模板里不放示例数据**（示例在 `examples/`）。**每个占位符上方都写明了生成器必须遵守的结构**，以模板里的注释为准：

  | 模板 | 占位符 | 粒度 | 替换成 |
  |------|--------|------|--------|
  | home-index.html | `@LEARN:SUBJECT_CARDS` | 区块 | 全部科目卡片（`learn-subject-list` > `syo-card.learn-subject-card`） |
  | subject-index.html | `@LEARN:TITLE` | 字段 | 科目名（`<title>` 与 `<h1>` 两处都替换） |
  | subject-index.html | `@LEARN:STATUS` | 字段 | 科目状态徽标（`syo-tag.learn-status.learn-status--active/--paused/--done`） |
  | subject-index.html | `@LEARN:MISSION` | 字段 | 使命一句话（MISSION.md 的 Why 第一句） |
  | subject-index.html | `@LEARN:PROJECT` | 区块 | 项目里程碑（progress.yaml 的 project；没有项目时输出 `.learn-project__none` 提示） |
  | subject-index.html | `@LEARN:ROADMAP` | 区块 | 分层路线图（`learn-roadmap` > `learn-level` > `learn-node`）；有课件的节点是 `details.learn-slot` + `summary.learn-node` + 子卡片组 `.learn-node__children`（点父卡片长出子卡片，父卡片不变大） |
  | subject-index.html | `@LEARN:ATTACHMENTS` | 区块 | 附件分组（参考文档 / 术语与资源 / 学习记录 / 会话摘要；空分组整组省略） |

  - **class 约定**：状态着色用 class（`learn-node--todo` / `--learning` / `--done` / `--review` / `--verified`；学习中与初步理解同用 `--learning`）而非内联颜色；生成器只输出结构 + class，CSS 在模板里
  - **生成的数值不占位**：状态概览条、知识点与课件计数由页面脚本从 DOM 统计，生成器不必准备占位符（无 JS 时显示 `–`，不会显示错误的 0）
  - 生成器必须**原样保留模板其余内容**（样式、脚本、文案都不能丢），只替换占位符行；区块占位符缺失时报错退出（防止模板被改坏后静默生成残缺页面）；输出到工作区
- **新课程先盘问（总控执行）**：学生报新科目时，**由总控亲自**盘问（设计树 + 分轮次，`ask_user_question` 一次问整个 frontier）问清：想学到什么程度、配合做什么项目、动手实操用什么方式（载体），以及其他必要决策；事实（记忆里已有的基础等）由总控自己查，不问用户；子 agent 不与用户交互，盘问不派给角色；盘问结果写入 subject.yaml / MISSION.md / MEMORY.md / `lab/README.md`（载体），随 prompt 传给 curriculum-designer 作为课程深度依据
- **科目元数据维护契约**（四份低频文件，**全部由总控直接维护**——总控全程在场判断最准，为小改动派角色再转一圈不划算；**不允许**每次会话无脑重写）：

  | 文件 | 触发时机 | 规则 |
  |---|---|---|
  | `subject.yaml` | 科目状态变化（开课/暂停/完成）、目标变更 | 只改 `status`/`goal`；`goal` 变更须先跟学生确认；改后过 schema |
  | `MISSION.md` | 学生的目标 / 配合项目 / 约束变了 | **必须先经学生确认**；旧使命留痕（改对应分节或追加"变更"小节），不整篇替换 |
  | `RESOURCES.md` | 新资料被课件采用、发现资源失效/低质 | **定位：延伸阅读 + 易变内容的核对来源**；只收高可信来源、每条带一行用途；失效的删除而非堆积 |
  | `GLOSSARY.md` | 学生**真能用对**某术语时（不是刚被介绍过） | 只收已掌握的术语；定义一两句 + 标出要避免的别名；课件用词以此为准 |

  - **分派原则**：**信息源在总控上下文里的工作总控自己做**——答疑、盘问、使命确认、四份元数据、以及全部档案记录（进度、误解、会话摘要、学习记录、共享记忆、主页刷新，按 `record-keeping` 执行）；**需要外部检索／大量生成／独立验证的工作才派角色**——拟大纲（课程设计）、做课件（讲解）、出题与证据核验（练习评估）
  - 三份 `.md` 无 schema（弱约束，按 `templates/*.md` 的分节写）；**学生可以手改**，下次会话生效
  - 发现科目间冲突（如术语表与课件用词不一致）→ 总控裁决，不自行改别的科目的文件
- 阶段一不依赖阶段二；主页任务（Task 13、14）可在阶段一验收后单独执行

### 主页先行路径（用户选择先做主页框架）

主页体系不依赖学习引擎（Task 4-9），可独立先做。会话顺序：

1. **会话 A**：Task 1（脚手架：README、.gitignore、check_skill.py）
2. **会话 B**：Task 3（模板，重点是 `home-index.html`、`subject-index.html` 两个主页模板——骨架与样式在模板里，数据位置留占位符，生成器只做注入）
3. **会话 C**：Task 11 最小版——只做 install.sh 的"③ 学习工作区"部分（建 `workspace/` + 写 `~/.dsh/studymate-config.yaml`），把 skill 目录写进预设这一步留到学习引擎完成后补跑（install.sh 幂等，重复跑即可补全）
4. **会话 D**：Task 13（`gen_home.py`：读配置 → 读示例数据 → 生成根主页 + 科目主页）。示例数据先用最小假数据（临时建 1-2 个科目 yaml），等 Task 12 完成后用真实示例替换
5. **会话 E**：Task 14（主页与学习流程打通，learning-system 调用 gen_home.py——此步若 Task 9 未完成，先验证"改状态文件 → 跑脚本 → 主页更新"的闭环，学习引擎接入后自动生效）

主页路径完成后再按 DAG 主路径补 Task 2、4-9、10、11 完整版、12。

- [ ] **Step 3: 创建 `scripts/check_skill.py`**

不要用 `yaml.safe_load` 直接读整个 `SKILL.md`：文件里有 frontmatter 和正文两段，safe_load 会因"多文档"报 ComposerError（已实测）。先切出 frontmatter 再解析。

```python
#!/usr/bin/env python3
"""校验 SKILL.md 的 frontmatter：解析、name 与目录名一致、按目录角色断言调用方式。

用法：
  python3 scripts/check_skill.py <skill目录> [<skill目录> ...]
  python3 scripts/check_skill.py .dsh/skills/learning-coach --expect-role
  python3 scripts/check_skill.py .dsh/skills/learning-system --expect-model-invocable
"""
import os
import re
import sys

import yaml

FRONTMATTER = re.compile(r'^---\r?\n(.*?)\r?\n---\r?\n', re.S)


def read_frontmatter(skill_dir):
    path = os.path.join(skill_dir, 'SKILL.md')
    text = open(path, encoding='utf-8').read()
    match = FRONTMATTER.match(text)
    if not match:
        raise SystemExit(f'FAIL {skill_dir}: frontmatter 缺失或格式不对（需以 --- 开头并闭合）')
    return yaml.safe_load(match.group(1)) or {}


def main(argv):
    dirs = [a for a in argv if not a.startswith('--')]
    flags = {a for a in argv if a.startswith('--')}
    if not dirs:
        raise SystemExit(__doc__)
    failed = False
    for skill_dir in dirs:
        meta = read_frontmatter(skill_dir)
        expected_name = os.path.basename(skill_dir.rstrip('/'))
        problems = []
        if meta.get('name') != expected_name:
            problems.append(f"name={meta.get('name')!r} 与目录名 {expected_name!r} 不一致")
        if not meta.get('description'):
            problems.append('description 缺失')
        model_invocable = 'disable-model-invocation' not in meta
        if '--expect-model-invocable' in flags and not model_invocable:
            problems.append('本 skill 应允许模型直接调用，但设了 disable-model-invocation')
        if '--expect-role' in flags and model_invocable:
            problems.append('角色/协议 skill 需设 disable-model-invocation: true')
        if problems:
            failed = True
            print(f'FAIL {skill_dir}: ' + '；'.join(problems))
        else:
            print(f'OK   {skill_dir}')
    return 1 if failed else 0


if __name__ == '__main__':
    sys.exit(main(sys.argv[1:]))
```

# 四层练习指引

四层是默认进阶路径，不是必须逐级走完的台阶：学生已在项目里用过某知识点，可以从高层起步；某层反复卡住，可以退回来补。

| 层 | 类型 | 出题要求 | 通过标准 |
|----|------|---------|---------|
| L1 理解 | 判断/解释/预测输出 | 每题追问"为什么" | 能解释原因，不只给结论 |
| L2 改造 | 修改已有代码观察变化 | 给可运行的 10-20 行代码，指定一处改动 | 能预测改动结果并运行验证 |
| L3 排错 | 真实 bug 定位 | 给含 1-2 个 bug 的代码或真实报错 | 能说出根因 + 修复 + 预防 |
| L4 应用 | 放进真实项目 | 任务挂到当前项目里程碑，交付物明确 | 代码跑通 + 测试通过 + 能解释取舍 |

# 完成证据核验协议

判断一个节点是否"能独立应用"，以证据为准。证据按可信度排序：

1. **运行结果**：代码或测试真实运行通过
2. **测试代码**：学生自己写的测试覆盖了关键行为
3. **解释能力**：能说清"为什么这样设计、哪里可能出错"
4. **口头确认**：单独出现时不足以判定通过

## 核验流程

- 每个 L3/L4 交付物，对照该节点 `evidence` 字段逐条核验
- 核验时实际运行（能跑就跑，运行失败即证据不成立），反馈具体报错
- 输出三档结论：`通过 / 部分通过（列出缺哪条）/ 不通过（列出原因）`，并给出"差一步就能过"的具体建议

## 硬的边界

- 结论必须能指向一条具体证据；无法指向时按"不通过"处理
- 运行只用于核验，学生的项目代码由学生自己写

## 题目系统重构（v2）——本节覆盖以下旧快照

**为什么做**：题目此前有四个来源（课件选择题、课件动手块、lab 的任务与断言、评估角色现场出题）与四个隐性 owner，计划里没有一条正面规定"题归谁"；同一处知识被问三遍而互不引用；`evidence` 这个字段名从没被解释过。v2 把"题"收成**单一 owner**，并把项目里程碑变成大纲里的一种课。

### 1. Owner 与产物

- **`practice-evaluator` 是题目唯一 owner**：题面、答案、算过标准、lab 实操题（教程／留白任务／断言／`package.json`／`solutions/`）、实验课的说明页内容，全部由它产出；**它不写文件**，内容交总控写盘。
- **`learning-coach` 不再出题**：只写课件正文（讲解 + 轻量跟做），并在**回合二**把出题人给的题**原样**嵌进正文；位置与引入行文归它，题面与答案一个字不改。
- 其它角色不碰题：`lesson-design` 管课件呈现（**题目与 lab 不归它管**）；`curriculum-designer` 只决定"这课是什么类型"。

### 2. 四种题型与数据契约

| 题型 | 长什么样 | 判分 |
|------|---------|------|
| 选择题 | 页内 `.quiz`，点选项即时反馈 + 一句 `why` | 页内自动判 |
| 开放题 | 页内出题，**参考答案 + 算过标准点击展开**（不贴回会话） | 学生自评 |
| 实操题 | `lab/` 留白任务 + 断言 + `solutions/` | `npm test` 自动判 |
| 评估题 | 评估时现场出的 1-2 题（开放） | `practice-evaluator` 判 |

**字段契约的唯一出处是 `templates/assets/quiz.js` 顶部注释**：选择题 `q/opts/ans/why`，开放题 `q/answer/criteria`，一题只能二选一。闸门按它逐题校验结构。

### 3. 三种课型（`curriculum.yaml` 节点的 `kind`，必填）

| `kind` | 是什么 | 产出 | 题目上限 |
|--------|--------|------|---------|
| `概念` | 普通课，只讲不落 lab | 课件（讲解 + 轻量跟做） | L3 |
| `实操` | 普通课，带自己的小 lab | 课件 + lab | L4 |
| `实验` | **里程碑验收课**：与普通课同级插在大纲里，验收"学到目前的知识能做出什么" | **实验说明页**（任务书）+ 验收任务 | L4 |

- 里程碑**不是** `progress.yaml` 里的元数据：它就是 `kind: 实验` 的节点，`prerequisites` 列出它验收哪些课。
- 实验课通过后：实验课节点与它的 `prerequisites` 全部置「已通过项目验证」，并写一条学习记录——这是"项目推进"的唯一依据。
- 概念题的**题量按学生作答总时长 ≤10 分钟估**（不设题数下限，也不硬性限题数）。
- L1-L4 是**题目**的层级词汇（评估记录里记 `layer`），不写进页面，也不用来标动手步骤。

### 4. 一个节点的产出流程

```
概念 / 实操课：coach（回合一·正文 + 题目位标记）→ evaluator（时机一·出题；实操课另产整套 lab）
              → 总控写盘 lab → coach（回合二·原样嵌题）→ 闸门 → 打开页面
实验课：      evaluator（时机一·实验任务：说明页内容 + 验收任务）→ 总控按骨架写盘 → 闸门 → 打开说明页
评估：        学生说"学完了" → evaluator（时机二·评估；实操课与实验课走证据核验）→ 总控落评估记录
```

### 4b. 对话节奏（每轮以「下一步」收尾）

从开课到结课，**总控每一轮回复的最后一行都要是「下一步」**：`<谁做什么> —— <怎么触发>`，具体到角色/文件/触发词；大纲刚生成、课件刚产出、评估刚出结论、局部提问刚答完、会话结束时都要有（结课时给"下次从哪继续"）。分寸：不重复问同一个问题（上一轮问过"开始吗"还没答就别再问）、学生说"今天到这"就不再推。

### 4c. 调试期移除样板课件（待重建）

`examples/` 里那份样板课件（`lessons/0001-http-basics.html`）已删除、`lessons/` 目录随之消失——原因是**骨架注释把讲解角色指去读它当范本**（`templates/lesson.html` 的代码块说明），导致"不管怎么改规范都有一股模板味"：实测三份旧课件 h2 与它逐字同构（含「这些词的来历：先有麻烦，才有名字」）。骨架里的 `.syo-editor` 写法已改为**内联**。等调试阶段结束再重做一份样板（届时同步 Task 12 里针对该文件的 Create/Step 7/验收断言与 `.preview` 路径说明）。

### 5. 闸门与留痕

## 课件命名与上下节指针（v3）

**背景**：课件页要在侧栏底部给「上节课 / 下节课」两个入口。下节课通常还没产出，所以那是一个**悬空指针**——
指针要能预写，就必须让"下节课叫什么"在写上一课时已经确定。节点 id 与顺序在 `curriculum.yaml` 里先于课件存在，
于是把文件名绑到节点上即可。

**规则**：`lessons/<NNNN>-<节点id>.html`，NNNN = 节点在 `curriculum.yaml` 的 `nodes:` 里的序号（4 位，从 0001）。
一个节点一节课件。上一课的「下节课」按这条规则预写，下一课照规则起名 → 链接自己就通，**零回填**。

**指针**：课件正文末尾由讲解角色写一段真实链接（js 关掉也还在）：

```html
<nav class="lesson-nav" aria-label="上一课 / 下一课">
  <a class="lesson-nav__link lesson-nav__link--prev" href="0001-overview-map.html">…上节课…</a>
  <a class="lesson-nav__link lesson-nav__link--next" href="0003-io-and-vars.html">…下节课…</a>
</nav>
```

`lesson-toc.js` 生成目录后把它**搬到侧栏目录下面**（页面上只有一份）；样式在 `templates/assets/style.css`
的 `.lesson-nav*`；第一课不写 `--prev`、最后一课不写 `--next`、单节点科目整块不出现。

**闸门**（`check_lesson.py` 检查项 8，需 `--subject/--node`，邻居取自大纲顺序，两条都拦）：
① 文件名 = `<序号>-<节点id>.html`；② `--prev`/`--next` 正好指向大纲里的前后邻居（有邻居就得写、没有就不许写）。
指针指向的文件不存在只提示（悬空指针是常态）。

**落地时改了什么**：`lesson-design` §四（命名 + 指针）、`learning-coach` 回合 1 第 2 条、`templates/lesson.html`
（头部用法 + 组件说明 + 正文末尾的 nav 块）、`templates/assets/lesson-toc.js`（搬移逻辑）、`templates/assets/style.css`
（`.lesson-nav*` 样式）、`templates/assets/README.md`、`check_lesson.py`；现有 `0002-compile-and-run.html`
按规则改名 `0002-first-program.html`（引用它的科目页由 `gen_home.py` 重新生成），0001/0002 补上指针。

**二阶效应**：文件名不再是人取的 slug（可读性略降，换来指针/脚本/大纲三处同源）；**大纲插删节点会让已写好的
指针指错**，闸门 ①② 会报出来，需要人工改指针；一个节点只能一节课；「下节课」在产出前点了是浏览器"文件不存在"
（`file://` 下无法探测文件是否存在，这是悬空指针的代价）；手机上侧栏是抽屉，要展开才看得到这两个入口。
