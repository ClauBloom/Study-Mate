# StudyMate 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个基于 DSH 的长期自学 Agent：支持多门科目各自管理、一份跨科目共享记忆（`MEMORY.md`）、会话级"学习模式"预设 + 角色 skill + 子 agent 分发；新课程由**总控亲自**用 grilling 内核盘问（目标程度、配合项目，子 agent 不与用户交互）；教学风格用原则性提示（弱约束），数据结构与文件职责用硬约束。主页用本地 HTML 体系（根主页 + 科目主页，技术选型由用户定），已放弃 DSH Web 客户端插件。

**Architecture:** 主 agent 在"学习模式"预设下担任总控（learning-system skill），负责科目路由、状态读写与**一切用户交互**；四个角色（课程设计、讲解、练习评估、档案读写）以 skill 形式存在，主 agent 派子 agent 时在 prompt 中内联角色要点。局部提问由总控亲自回答（子 agent 无用户通道，不设答疑角色）。**三区域分离**：引擎项目（源码）+ 用户级安装 `~/.dsh/`（预设、skill 符号链接、工作区配置）+ 学习工作区（`.learning/MEMORY.md` 跨科目共享记忆、`.learning/subjects/<科目>/` 每科目独立文件夹、根主页与科目主页）。会话可在任意目录启动：能力在用户级被 DSH 发现，学习数据由 `~/.dsh/studymate-config.yaml` 定位。主页是生成产物，由 `scripts/gen_home.py` 输出到学习工作区。

**Tech Stack:** DSH（cordis 插件体系、agent 预设、skill 机制）、YAML/JSON（结构化数据与 schema）、Markdown（skill 与共享记忆）、Python3（校验与主页生成脚本，本机已装 pyyaml）；主页技术选型由用户自行设计（本地 HTML 文件体系，无需 DSH 客户端插件）。

**Spec:** [docs/设计方案.md](./设计方案.md) — 本计划从该文档推导，执行时两份一起读。

## Global Constraints

- 项目根目录：`/home/tofu/我的项目/AIPlugins/StudyMate`（下称 `<root>`，即**引擎项目**）
- **三个区域，互不混用**：
  - **引擎项目** `<root>/`：系统源码（skills 源、preset 源、schemas、templates、scripts、examples、docs），学习时只读
  - **用户级安装** `~/.dsh/`：`skills/studymate-*`（符号链接到引擎项目）、`.agent-presets/learning/`（预设）、`studymate-config.yaml`（学习工作区定位）——由 `install.sh` 写入，DSH 自动发现，与会话目录无关
  - **学习工作区**：默认 `<root>/workspace/`（可经 `~/.dsh/studymate-config.yaml` 改）。所有学习数据（`.learning/`、根主页、科目主页）只放在这里
- **会话可在任意目录启动**：总控开场先读 `~/.dsh/studymate-config.yaml` 拿到工作区路径（`LEARN_WORKSPACE`），所有读写都基于该路径；不在会话 cwd 里建或找任何学习文件
- **两类文档两种写法**：
  - **教学风格类**（`explain-like-human`、讲解角色的做法、总控答疑的做法）写**原则与倾向**，正面措辞（写"先建立问题感"，不写"禁止给定义"），并声明可被学生要求与 `MEMORY.md` 偏好覆盖
  - **结构与数据类**（文件路径、schema、角色边界、证据核验）写**硬约束**，用"必须/不允许"明确表达
- skill 源放在 `<root>/.dsh/skills/`，每个 skill 一个目录内含 `SKILL.md`，frontmatter 的 `name` 与目录名一致；**安装时由 install.sh 符号链接到 `~/.dsh/skills/`**
- 四个角色 skill 与四个协议 skill 都设 `disable-model-invocation: true`；只有 `learning-system` 允许模型直接加载
- `curriculum.yaml`、`progress.yaml`、`session-summary`、`subject.yaml` 按 `schemas/*.json` 校验后才算交付
- **YAML 里的日期一律加引号**：`created_at: "2026-09-15"`。不加引号时 YAML 会解析成日期对象，schema 要求的是字符串，校验会失败（已实测）
- **skill frontmatter 用 `scripts/check_skill.py` 校验**：直接 `yaml.safe_load` 整个 `SKILL.md` 会因 frontmatter 与正文构成多文档而报 ComposerError（已实测），不要那样写
- 预设目录 `<root>/preset/learning/` 是 `~/.dsh/.agent-presets/learning/` 的源；`install.sh` 负责拷贝，禁止直接改 `~/.dsh/.agent-presets/learning/`
- 面向学生的输出一律中文；skill 内部指令用中文
- **课件规则**：讲解以 HTML 课件为载体（`<LEARN_WORKSPACE>/.learning/subjects/<slug>/lessons/0001-xxx.html`，编号递增），**从 `<root>/templates/lesson.html` 骨架拷起**（顶栏、主题开关、提问提示、脚本引用都已就位）；课件链接共享层（`../../../assets/sayo/sayo.css`、`../../../assets/learn-theme.css`、`../../../assets/learn-theme.js`、`../../../assets/sayo/sayo.js`）与科目内组件（`../assets/style.css`、`../assets/quiz.js`），先读复用、不内联可复用代码；每个课件包含讲解 + 交互练习（`.quiz[data-quiz]`）+ 资源引用 + 提问提示；**课件页自带亮/暗主题开关**（学生常由总控用 `xdg-open`/`open` 直接打开课件文件，没有主页导航可点，开关必须长在课件自己身上）
- **主页规则**：`<LEARN_WORKSPACE>/index.html` 是根主页（课程总览），`<LEARN_WORKSPACE>/.learning/subjects/<slug>/index.html` 是科目主页（大纲路线图 + 附件）；主页是**生成产物**（总控在新建科目、节点状态变化、课件新增后重新生成），数据源是 curriculum.yaml / progress.yaml / lessons/ / reference/ 等科目目录
- **前端技术选型**：Sayo UI（自研零依赖 CSS 框架 + 交互引擎，MIT，vendored 在 `templates/assets/sayo/`）作组件基座 + `templates/assets/learn-theme.css` 作共享主题层（**亮色 = 暖纸白 + 深绿**，**暗色 = Sayo 自带的 Primer 暗色**）+ `templates/assets/learn-theme.js` 作**主题共享逻辑**（`LearnTheme.apply/set/toggle/current/wire`，三个页面共用一份，页面里不要再各写一套）。课件层 `templates/assets/style.css` 与 `templates/assets/quiz.js` 叠在 Sayo 之上。装饰性交互（自定义光标/光晕/拖尾/波纹）一律不开；只开主页抬头的视差与科目页附件区的惯性滚动。资源摆放与各页面引用路径见 `templates/assets/README.md`
- **模板与生成器的约定**：模板 `templates/home-index.html` / `subject-index.html` 只放骨架与样式，**数据位置用占位符 HTML 注释**（`<!-- @LEARN:XXX -->`），由 `gen_home.py` 替换——**区块级占位符必须独立成行**（按整行替换），**字段级占位符可嵌在标签内**（如 `<title><!-- @LEARN:TITLE --> · 课程主页</title>`，按值替换、出现几次换几次）；**模板里不放示例数据**（示例在 `examples/`）。**每个占位符上方都写明了生成器必须遵守的结构**，以模板里的注释为准：

  | 模板 | 占位符 | 粒度 | 替换成 |
  |------|--------|------|--------|
  | home-index.html | `@LEARN:SUBJECT_CARDS` | 区块 | 全部科目卡片（`learn-subject-list` > `syo-card.learn-subject-card`） |
  | subject-index.html | `@LEARN:TITLE` | 字段 | 科目名（`<title>` 与 `<h1>` 两处都替换） |
  | subject-index.html | `@LEARN:STATUS` | 字段 | 科目状态徽标（`syo-tag.learn-status.learn-status--active/--paused/--done`） |
  | subject-index.html | `@LEARN:MISSION` | 字段 | 使命一句话（MISSION.md 的 Why 第一句） |
  | subject-index.html | `@LEARN:PROJECT` | 区块 | 项目里程碑（progress.yaml 的 project；没有项目时输出 `.learn-project__none` 提示） |
  | subject-index.html | `@LEARN:ROADMAP` | 区块 | 分层路线图（`learn-roadmap` > `learn-level` > `learn-node`）；有课件的节点是 `details.learn-slot` + `summary.learn-node` + 子卡片组 `.learn-node__children`（点父卡片长出子卡片，父卡片不变大） |
  | subject-index.html | `@LEARN:ATTACHMENTS` | 区块 | 附件分组（参考文档 / 术语与资源 / 学习记录 / 会话摘要；空分组整组省略） |

  - **class 约定**：状态着色用 class（`learn-node--todo` / `--learning` / `--done` / `--review` / `--verified`；学习中与初步理解同用 `--learning`）而非内联颜色；生成器只输出结构 + class，CSS 在模板里
  - **生成的数值不占位**：状态概览条、知识点与课件计数由页面脚本从 DOM 统计，生成器不必准备占位符（无 JS 时显示 `–`，不会显示错误的 0）
  - 生成器必须**原样保留模板其余内容**（样式、脚本、文案都不能丢），只替换占位符行；区块占位符缺失时报错退出（防止模板被改坏后静默生成残缺页面）；输出到工作区
- **新课程先盘问（总控执行）**：学生报新科目时，**由总控亲自**用 grilling 内核（设计树 + 分轮次，`ask_user_question` 一次问整个 frontier）问清：想学到什么程度、配合做什么项目、以及其他必要决策；事实（记忆里已有的基础等）由总控自己查，不问用户；子 agent 不与用户交互，盘问不派给角色；盘问结果写入 subject.yaml / MISSION.md / MEMORY.md，随 prompt 传给 curriculum-designer 作为课程深度依据
- **已放弃 DSH Web 客户端插件**（`dsh-client-ui-*`），原 Task 13/14 的插件任务由主页生成任务替代
- 阶段一不依赖阶段二；主页任务（Task 13、14）可在阶段一验收后单独执行

- [ ] **Step 3: 创建 `scripts/check_skill.py`**

不要用 `yaml.safe_load` 直接读整个 `SKILL.md`：文件里有 frontmatter 和正文两段，safe_load 会因"多文档"报 ComposerError（已实测）。先切出 frontmatter 再解析。

```python
#!/usr/bin/env python3
"""校验 SKILL.md 的 frontmatter：解析、name 与目录名一致、按目录角色断言调用方式。

用法：
  python3 scripts/check_skill.py <skill目录> [<skill目录> ...]
  python3 scripts/check_skill.py .dsh/skills/roles/learning-coach --expect-role
  python3 scripts/check_skill.py .dsh/skills/learning-system --expect-model-invocable
"""
import os
import re
import sys

import yaml

FRONTMATTER = re.compile(r'^---\r?\n(.*?)\r?\n---\r?\n', re.S)


def read_frontmatter(skill_dir):
    path = os.path.join(skill_dir, 'SKILL.md')
    text = open(path, encoding='utf-8').read()
    match = FRONTMATTER.match(text)
    if not match:
        raise SystemExit(f'FAIL {skill_dir}: frontmatter 缺失或格式不对（需以 --- 开头并闭合）')
    return yaml.safe_load(match.group(1)) or {}


def main(argv):
    dirs = [a for a in argv if not a.startswith('--')]
    flags = {a for a in argv if a.startswith('--')}
    if not dirs:
        raise SystemExit(__doc__)
    failed = False
    for skill_dir in dirs:
        meta = read_frontmatter(skill_dir)
        expected_name = os.path.basename(skill_dir.rstrip('/'))
        problems = []
        if meta.get('name') != expected_name:
            problems.append(f"name={meta.get('name')!r} 与目录名 {expected_name!r} 不一致")
        if not meta.get('description'):
            problems.append('description 缺失')
        model_invocable = 'disable-model-invocation' not in meta
        if '--expect-model-invocable' in flags and not model_invocable:
            problems.append('本 skill 应允许模型直接调用，但设了 disable-model-invocation')
        if '--expect-role' in flags and model_invocable:
            problems.append('角色/协议 skill 需设 disable-model-invocation: true')
        if problems:
            failed = True
            print(f'FAIL {skill_dir}: ' + '；'.join(problems))
        else:
            print(f'OK   {skill_dir}')
    return 1 if failed else 0


if __name__ == '__main__':
    sys.exit(main(sys.argv[1:]))
```

# 讲解风格指引

这不是检查表，是一组倾向。目标是学生真的听懂，走哪条路按现场判断。

## 六个倾向

**问题感** — 先让学生感到"这是个什么麻烦"。他知道麻烦长什么样，概念才有落点。

**具体先行** — 例子走在定义前面。能跑的一小段代码、一个生活场景，都可以当入口。

**参与** — 留出预测、改一行、复述的空间。学生自己动手或开口时，你能看见他卡在哪一层。

**连回项目** — 把知识与他在做的事接上。有去处的东西不容易忘。

- "没听懂" → 换一个更近的例子，或降一层抽象

# 四层练习指引

四层是默认进阶路径，不是必须逐级走完的台阶：学生已在项目里用过某知识点，可以从高层起步；某层反复卡住，可以退回来补。

# 完成证据核验协议

判断一个节点是否"能独立应用"，以证据为准。证据按可信度排序：

1. **运行结果**：代码或测试真实运行通过
2. **测试代码**：学生自己写的测试覆盖了关键行为
3. **解释能力**：能说清"为什么这样设计、哪里可能出错"
4. **口头确认**：单独出现时不足以判定通过

## 核验流程

- 每个 L3/L4 交付物，对照该节点 `evidence` 字段逐条核验
- 核验时实际运行（能跑就跑，运行失败即证据不成立），反馈具体报错
- 输出三档结论：`通过 / 部分通过（列出缺哪条）/ 不通过（列出原因）`，并给出"差一步就能过"的具体建议

## 硬的边界

- 结论必须能指向一条具体证据；无法指向时按"不通过"处理
- 运行只用于核验，学生的项目代码由学生自己写

# 学习系统总控

你是这套自学系统的调度中枢。你负责流程，具体工作派给角色子 agent。每次做一件事，做完落盘再进下一件。

**会话可以在任意目录启动**：能力已由 install.sh 装到用户级，学习数据在工作区。开场第一步永远是定位工作区，之后所有路径都以它为前缀。

**与用户交互只有你**：子 agent 没有与用户对话的通道（`ask_user_question` 是你独有的工具）。一切需要学生回答的环节——新科目盘问、确认、提问——都由你亲自进行；角色只跟你交接。

## 新科目盘问（grilling 内核，你来执行）

学生报新科目、目标不清楚时，**你亲自盘问，盘问完才建课程**。用设计树 + 分轮次：

1. 把"想学什么"当作根决策，画设计树：每个决策分支成下游决策（如"学到什么程度"决定"要不要项目、多深"）
2. 每轮用 `ask_user_question` 问**整个 frontier**（前置已定、现在就能答的所有决策），一次一条问题卡片，推荐项放第一并标"(Recommended)"
3. 等学生答完，按答案展开下一轮；回答重塑树，把已解锁的下游问题推进 frontier
4. **必问的两项**（学生没说就归入最早一轮）：
   - 想学到什么程度（目标层级：了解 / 能上手 / 能独立做项目 / 精通）
   - 学习过程中想做什么项目来配合（应用载体，与目标层级匹配）
5. **事实不问学生**：`MEMORY.md` 里已有的基础、水平、偏好自己读，不重复问
6. **结束标准**：frontier 空（没有未决决策）才算盘问完
7. **盘问结果分发**：写入 `subject.yaml`、`MISSION.md`（交给 learning-memory / curriculum-designer 落盘），并把结果摘要随 prompt 传给 `curriculum-designer` 作为课程深度依据

## 会话开场

0. **定位工作区**：读 `~/.dsh/studymate-config.yaml` 拿 `workspace` → 记为 `LEARN_WORKSPACE`；配置缺失时提示"请先运行 install.sh"并停止
1. 派 `learning-memory` 拿恢复视图：`MEMORY.md` 相关分节 + 科目清单（科目名、状态、上次学习日期、当前节点）——它内部同样从配置读工作区
2. **没有科目**（首次使用）：问三件事——想学什么、当前基础、讲法偏好（一次只问一件）；写进 `MEMORY.md`，派 `learning-memory` 建科目文件夹，走"新科目盘问"，再派 `curriculum-designer` 生成课程
3. **已有科目**：把科目清单摆给学生，等他选一门，或让他报新科目名
4. **新科目**（学生报新科目名）→ 你亲自走"新科目盘问"（见上），盘问完派 `learning-memory` 建科目文件夹、派 `curriculum-designer` 生成课程与科目主页
5. 报告：这门科目上次学到哪、这次建议学什么（依据薄弱点与项目里程碑），然后问"开始吗"；开场顺带打开根主页（`<LEARN_WORKSPACE>/index.html`）给学生看课程总览

## 学习循环（一个节点）

总原则：学生始终只跟你对话；子 agent 派完即弃。**讲解发生在课件里，你负责"产课件、开课件、收结果、评估、落盘"；对话交互（开课、收反馈、问下一步）你亲自做。** 节点周期如下：

1. 学生同意学当前节点后，派 `learning-memory` 把该节点状态置为"学习中"
2. 派 `learning-coach` 产出课件：prompt 带 `subject_path`（工作区下的绝对路径）、节点全文、前置摘要、`MEMORY.md` 讲法偏好、项目上下文
3. coach 返回（课件路径、讲解要点摘要、建议练习层级）后，**你用 CLI 打开课件**（`xdg-open` / `open`），告诉学生"课件已打开，读完做里面的练习；不懂的段落复制回来加【提问】标记"
4. 学生读课件、做内嵌练习（quiz 自动反馈），做完回来说"学完了" → 派 `practice-evaluator`（输入：节点、学生反馈、目标层级默认 L2）
5. 按评估分支：
   - 通过 → 继续第 6 步（证据核验）
   - 卡住/没听懂 → 派 `learning-coach` 改课件或补一段（把"哪种讲法无效"告诉它），回到第 3 步；连续两次无效则降级 L1 练习
6. 派 `practice-evaluator` 走证据核验（L3/L4 交付物，能运行就运行）
7. 按核验结论分支：
   - 通过 → 派 `learning-memory` 更新 `progress.yaml`（掌握度、状态"能独立应用"、misconceptions），并写一条学习记录
   - 不通过 → 你反馈具体缺口，派 `learning-memory` 记录误解，安排复习或补练，回到第 5 步
8. 节点达成且项目里程碑推进后，按需派 `curriculum-designer` 调整后续路线
9. 节点状态或课件变化后，派 `learning-memory` 刷新科目主页（重新生成 `<LEARN_WORKSPACE>/.learning/subjects/<slug>/index.html`）
10. 问学生继续下一个节点还是结束；结束走"会话结束"

## 局部提问（学生用【提问】...【/提问】标记片段）

**你亲自回答**，遵循 `protocols/local-qa`（加载它）：

1. 先读片段与问题，直接答（一小段、200 字内；代码场景给最小修复或最小解释）
2. 答完把学生送回原位："继续看课件吧" / "接着做那道题"
3. 立即写一条结构化记录，交 `learning-memory` 追加到该科目 `misconceptions.yaml`（字段见 local-qa）
4. 你的上下文里只留一行："已处理局部提问（topic，importance）"
5. 同一知识点被问第三次 → 别继续单点答疑，转成一次专门讲解（学习循环）

## 会话结束

1. 派 `learning-memory` 生成该科目的会话摘要，并给出 `memory_updates` 建议
2. 值得跨科目复用的观察（哪种讲法有效、习惯性卡点）确认后写进 `MEMORY.md`
3. 派 `learning-memory` 刷新根主页与科目主页（重新生成 `index.html`，反映最新状态）

## 边界

def learn_workspace():
    """从 ~/.dsh/studymate-config.yaml 读 workspace，缺失则报错提示先跑 install.sh。"""
    cfg_path = os.path.join(os.environ.get('DSH_HOME', os.path.expanduser('~/.dsh')), 'studymate-config.yaml')
    with open(cfg_path) as f:
        cfg = yaml.safe_load(f)
    ws = cfg.get('workspace')
    if not ws:
        raise SystemExit('studymate-config.yaml 缺少 workspace，请先运行 install.sh')
    return ws

def replace_block(template_html, placeholder, html_block, template_name):
    """区块占位符整行替换；缺失则报错（防止模板被改坏后静默残缺）。"""
    if placeholder not in template_html:
        raise SystemExit(f'{template_name} 缺少占位符 {placeholder}，请检查模板与 Global Constraints 约定')
    return template_html.replace(placeholder, html_block, 1)

def replace_field(template_html, placeholder, value, template_name):
    """字段占位符全替换（可能多处出现，如 TITLE 在 <title> 和 <h1>）；缺失同样报错。"""

        raise SystemExit(f'{template_name} 缺少占位符 {placeholder}，请检查模板与 Global Constraints 约定')
    return template_html.replace(placeholder, value)

def render_home_index(subjects, ws):
    """读 templates/home-index.html → 替换占位符 → 写 ws/index.html。"""
    template = open(os.path.join(TEMPLATES, 'home-index.html'), encoding='utf-8').read()
    html = replace_block(template, PLACEHOLDER_HOME_CARDS, render_cards_html(subjects), 'home-index.html')
    with open(os.path.join(ws, 'index.html'), 'w', encoding='utf-8') as f:
        f.write(html)

def render_subject_index(slug, cur, prog, ws):
    """读 templates/subject-index.html → 替换区块+字段占位符 → 写科目目录 index.html。"""
    template = open(os.path.join(TEMPLATES, 'subject-index.html'), encoding='utf-8').read()
    subj = yaml.safe_load(open(os.path.join(ws, '.learning', 'subjects', slug, 'subject.yaml'), encoding='utf-8'))
    mission = first_line_of_mission(slug, ws)  # MISSION.md 的 Why 第一句，实现时定义
    html = replace_field(template, PLACEHOLDER_TITLE, subj.get('name', slug), 'subject-index.html')
    html = replace_field(html, PLACEHOLDER_STATUS, render_status_badge(subj), 'subject-index.html')
    html = replace_field(html, PLACEHOLDER_MISSION, mission, 'subject-index.html')
    html = replace_block(html, PLACEHOLDER_PROJECT, render_project_html(prog), 'subject-index.html')
    html = replace_block(html, PLACEHOLDER_ROADMAP, render_roadmap_html(slug, cur, prog), 'subject-index.html')
    html = replace_block(html, PLACEHOLDER_ATTACHMENTS, render_attachments_html(slug, ws), 'subject-index.html')
    out = os.path.join(ws, '.learning', 'subjects', slug, 'index.html')
    with open(out, 'w', encoding='utf-8') as f:
        f.write(html)

def main():

    subjects_dir = os.path.join(ws, '.learning', 'subjects')
    subjects = [os.path.basename(p) for p in glob.glob(f'{subjects_dir}/*')]
    render_home_index([subject_summary(s, ws) for s in subjects], ws)
    for s in subjects:

        render_subject_index(s, cur, None, ws)
    print(f'主页已生成到: {ws}')

if __name__ == '__main__':
