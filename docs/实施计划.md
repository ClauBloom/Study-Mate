# Learn-everything 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个基于 DSH 的长期自学 Agent：支持多门科目各自管理、一份跨科目共享记忆（`MEMORY.md`）、会话级"学习模式"预设 + 角色 skill + 子 agent 分发；新课程先用 grilling 内核盘问（目标程度、配合项目）；教学风格用原则性提示（弱约束），数据结构与文件职责用硬约束。主页用本地 HTML 体系（根主页 + 科目主页，技术选型由用户定），已放弃 DSH Web 客户端插件。

**Architecture:** 主 agent 在"学习模式"预设下担任总控（learning-system skill），负责科目路由与状态读写；五个角色（课程设计、讲解、局部问答、练习评估、档案读写）以 skill 形式存在，主 agent 派子 agent 时在 prompt 中内联角色要点。**三区域分离**：引擎项目（源码）+ 用户级安装 `~/.dsh/`（预设、skill 符号链接、工作区配置）+ 学习工作区（`.learning/MEMORY.md` 跨科目共享记忆、`.learning/subjects/<科目>/` 每科目独立文件夹、根主页与科目主页）。会话可在任意目录启动：能力在用户级被 DSH 发现，学习数据由 `~/.dsh/learning-config.yaml` 定位。主页是生成产物，由 `scripts/gen_home.py` 输出到学习工作区。

**Tech Stack:** DSH（cordis 插件体系、agent 预设、skill 机制）、YAML/JSON（结构化数据与 schema）、Markdown（skill 与共享记忆）、Python3（校验与主页生成脚本，本机已装 pyyaml）；主页技术选型由用户自行设计（本地 HTML 文件体系，无需 DSH 客户端插件）。

**Spec:** [docs/设计方案.md](./设计方案.md) — 本计划从该文档推导，执行时两份一起读。

## Global Constraints

- 项目根目录：`/home/tofu/我的项目/AIPlugins/Learn-everything`（下称 `<root>`，即**引擎项目**）
- **三个区域，互不混用**：
  - **引擎项目** `<root>/`：系统源码（skills 源、preset 源、schemas、templates、scripts、examples、docs），学习时只读
  - **用户级安装** `~/.dsh/`：`skills/learning-*`（符号链接到引擎项目）、`.agent-presets/learning/`（预设）、`learning-config.yaml`（学习工作区定位）——由 `install.sh` 写入，DSH 自动发现，与会话目录无关
  - **学习工作区**：默认 `<root>/workspace/`（可经 `~/.dsh/learning-config.yaml` 改）。所有学习数据（`.learning/`、根主页、科目主页）只放在这里
- **会话可在任意目录启动**：总控开场先读 `~/.dsh/learning-config.yaml` 拿到工作区路径（`LEARN_WORKSPACE`），所有读写都基于该路径；不在会话 cwd 里建或找任何学习文件
- **两类文档两种写法**：
  - **教学风格类**（`explain-like-human`、讲解/问答角色的做法）写**原则与倾向**，正面措辞（写"先建立问题感"，不写"禁止给定义"），并声明可被学生要求与 `MEMORY.md` 偏好覆盖
  - **结构与数据类**（文件路径、schema、角色边界、证据核验）写**硬约束**，用"必须/不允许"明确表达
- skill 源放在 `<root>/.dsh/skills/`，每个 skill 一个目录内含 `SKILL.md`，frontmatter 的 `name` 与目录名一致；**安装时由 install.sh 符号链接到 `~/.dsh/skills/`**
- 五个角色 skill 与三个协议 skill 都设 `disable-model-invocation: true`；只有 `learning-system` 允许模型直接加载
- `curriculum.yaml`、`progress.yaml`、`session-summary`、`subject.yaml` 按 `schemas/*.json` 校验后才算交付
- **YAML 里的日期一律加引号**：`created_at: "2026-09-15"`。不加引号时 YAML 会解析成日期对象，schema 要求的是字符串，校验会失败（已实测）
- **skill frontmatter 用 `scripts/check_skill.py` 校验**：直接 `yaml.safe_load` 整个 `SKILL.md` 会因 frontmatter 与正文构成多文档而报 ComposerError（已实测），不要那样写
- 预设目录 `<root>/preset/learning/` 是 `~/.dsh/.agent-presets/learning/` 的源；`install.sh` 负责拷贝，禁止直接改 `~/.dsh/.agent-presets/learning/`
- 面向学生的输出一律中文；skill 内部指令用中文
- **课件规则**：讲解以 HTML 课件为载体（`<LEARN_WORKSPACE>/.learning/subjects/<slug>/lessons/0001-xxx.html`，编号递增）；课件自包含、链接 `assets/` 组件（先读复用，不内联可复用代码）；每个课件包含讲解 + 交互练习 + 资源引用 + 提问提示；总控用 `xdg-open`/`open` 打开课件给学生
- **主页规则**：`<LEARN_WORKSPACE>/index.html` 是根主页（课程总览），`<LEARN_WORKSPACE>/.learning/subjects/<slug>/index.html` 是科目主页（大纲路线图 + 课件目录）；主页是**生成产物**（总控在新建科目、节点状态变化、课件新增后重新生成），数据源是 curriculum.yaml / progress.yaml / lessons/ 目录；技术选型由用户自行设计，模板 `templates/home-index.html` 与 `templates/subject-index.html` 只定信息结构
- **新课程先盘问**：学生报新科目时，先用 grilling 内核（设计树 + 分轮次，`ask_user_question` 一次问整个 frontier）问清：想学到什么程度、配合做什么项目、以及其他必要决策；事实（记忆里已有的基础等）由 agent 自己查，不问用户；盘问结果写入 subject.yaml / MISSION.md / MEMORY.md
- **已放弃 DSH Web 客户端插件**（`dsh-client-ui-*`），原 Task 13/14 的插件任务由主页生成任务替代
- 阶段一不依赖阶段二；主页任务（Task 13、14）可在阶段一验收后单独执行

- [ ] **Step 3: 创建 `scripts/check_skill.py`**

不要用 `yaml.safe_load` 直接读整个 `SKILL.md`：文件里有 frontmatter 和正文两段，safe_load 会因"多文档"报 ComposerError（已实测）。先切出 frontmatter 再解析。

```python
#!/usr/bin/env python3
"""校验 SKILL.md 的 frontmatter：解析、name 与目录名一致、按目录角色断言调用方式。

用法：
  python3 scripts/check_skill.py <skill目录> [<skill目录> ...]
  python3 scripts/check_skill.py .dsh/skills/roles/learning-coach --expect-role
  python3 scripts/check_skill.py .dsh/skills/learning-system --expect-model-invocable
"""
import os
import re
import sys

import yaml

FRONTMATTER = re.compile(r'^---\r?\n(.*?)\r?\n---\r?\n', re.S)


def read_frontmatter(skill_dir):
    path = os.path.join(skill_dir, 'SKILL.md')
    text = open(path, encoding='utf-8').read()
    match = FRONTMATTER.match(text)
    if not match:
        raise SystemExit(f'FAIL {skill_dir}: frontmatter 缺失或格式不对（需以 --- 开头并闭合）')
    return yaml.safe_load(match.group(1)) or {}


def main(argv):
    dirs = [a for a in argv if not a.startswith('--')]
    flags = {a for a in argv if a.startswith('--')}
    if not dirs:
        raise SystemExit(__doc__)
    failed = False
    for skill_dir in dirs:
        meta = read_frontmatter(skill_dir)
        expected_name = os.path.basename(skill_dir.rstrip('/'))
        problems = []
        if meta.get('name') != expected_name:
            problems.append(f"name={meta.get('name')!r} 与目录名 {expected_name!r} 不一致")
        if not meta.get('description'):
            problems.append('description 缺失')
        model_invocable = 'disable-model-invocation' not in meta
        if '--expect-model-invocable' in flags and not model_invocable:
            problems.append('本 skill 应允许模型直接调用，但设了 disable-model-invocation')
        if '--expect-role' in flags and model_invocable:
            problems.append('角色/协议 skill 需设 disable-model-invocation: true')
        if problems:
            failed = True
            print(f'FAIL {skill_dir}: ' + '；'.join(problems))
        else:
            print(f'OK   {skill_dir}')
    return 1 if failed else 0


if __name__ == '__main__':
    sys.exit(main(sys.argv[1:]))
```

````markdown
你负责一门科目的课程大纲与配套文件。学生不会直接调用你。

## 新科目的盘问（grilling 内核，硬流程）

学生报新科目、但目标还不清楚时，**先盘问再建课程**。用设计树 + 分轮次：

1. 把"想学什么"当作根决策，画设计树：每个决策分支成下游决策（如"学到什么程度"决定"要不要项目、多深"）
2. 每轮用 `ask_user_question` 问**整个 frontier**（前置已定、现在就能答的所有决策），一次一条问题卡片，推荐项放第一并标"(Recommended)"
3. 等用户答完，按答案展开下一轮；用户回答重塑树，把已解锁的下游问题推进 frontier
4. **必问的两项**（用户没说就归入最早一轮）：
   - 想学到什么程度（目标层级：了解 / 能上手 / 能独立做项目 / 精通）
   - 学习过程中想做什么项目来配合（应用载体，与目标层级匹配）
5. **事实不问用户**：`MEMORY.md` 里已有的基础、水平、偏好由你读出来用，不重复问
6. **结束标准**：frontier 空（没有未决决策）才算盘问完；盘问结果写入 subject.yaml、MISSION.md，需要跨科目记录的部分交总控写 MEMORY.md

## 职责

1. **初始化科目配套文件**（新科目时，盘问完成后）：
   - `MISSION.md`：按 `templates/MISSION.md` 填（Why / Success looks like / Constraints / Out of scope）；盘问结果直接落进 Why 与 Success looks like
   - `RESOURCES.md`：按 `templates/RESOURCES.md` 建知识资源清单；拿不准的来源标"待总控用 research 核实"
2. **生成新课程**：从科目目标与学生现有水平出发，按知识依赖建 DAG（有向无环图）
   - 每个节点包含：id、title、objective、problem、prerequisites、concepts、resources、practice、pitfalls、realworld、evidence、status（初始"未开始"）、mastery（0）
   - `resources` 只放权威来源（官方文档、教材、公认文章），每条带 title 与 url，并与 `RESOURCES.md` 保持一致（课件引用可查）
   - 节点粒度按"一次会话能完成一个学习单元"切
3. **调整课程**（学生卡住、加速、暴露薄弱点时）：
   - 改动限制在必要的节点与边上，已学节点的内容与状态保持原样

4. **校验**：写完后对照 `schemas/curriculum.schema.json` 校验；校验通过才算交付
5. **报告**：返回给总控一段简短变更说明（改了什么、为什么、影响哪些节点）

- 盘问不重复：已经问过并记录进 MISSION.md 的决策，后续不再问
````

````markdown
# 讲解风格指引

这不是检查表，是一组倾向。目标是学生真的听懂，走哪条路按现场判断。

## 六个倾向

**问题感** — 先让学生感到"这是个什么麻烦"。他知道麻烦长什么样，概念才有落点。

**具体先行** — 例子走在定义前面。能跑的一小段代码、一个生活场景，都可以当入口。

**小步** — 一次给一点。学生消化的速度比讲完的速度重要。

**学生的语言** — 沿用学生自己的说法；术语首次出现时顺带一句大白话。他用得上那个词，才算学会。

**参与** — 留出预测、改一行、复述的空间。学生自己动手或开口时，你能看见他卡在哪一层。

**连回项目** — 把知识与他在做的事接上。有去处的东西不容易忘。

## 学生反馈的处理倾向

- "没听懂" → 换一个更近的例子，或降一层抽象
- "太简单" → 加边界、加取舍、加反例
- 要答案 → 先给线索；还卡再加码
- "有什么用" → 先答用途，再回内容

## 覆盖关系

这些倾向是默认值。学生的明确要求、科目性质、任务紧急度都可以覆盖它们。`.learning/MEMORY.md` 里记录的个人偏好优先级最高——那份文件就是这套指引随人调整的地方。
````

````markdown
# 四层练习指引

四层是默认进阶路径，不是必须逐级走完的台阶：学生已在项目里用过某知识点，可以从高层起步；某层反复卡住，可以退回来补。

| 层 | 类型 | 出题要求 | 通过标准 |
|----|------|---------|---------|
| L1 理解 | 判断/解释/预测输出 | 每题追问"为什么" | 能解释原因，不只给结论 |
| L2 改造 | 修改已有代码观察变化 | 给可运行的 10-20 行代码，指定一处改动 | 能预测改动结果并运行验证 |
| L3 排错 | 真实 bug 定位 | 给含 1-2 个 bug 的代码或真实报错 | 能说出根因 + 修复 + 预防 |
| L4 应用 | 放进真实项目 | 任务挂到当前项目里程碑，交付物明确 | 代码跑通 + 测试通过 + 能解释取舍 |

- L4 任务写成可核验的（核验方式见 `protocols/evidence-check`）
````

````markdown
# 完成证据核验协议

判断一个节点是否"能独立应用"，以证据为准。证据按可信度排序：

1. **运行结果**：代码或测试真实运行通过
2. **测试代码**：学生自己写的测试覆盖了关键行为
3. **解释能力**：能说清"为什么这样设计、哪里可能出错"
4. **口头确认**：单独出现时不足以判定通过

## 核验流程

- 每个 L3/L4 交付物，对照该节点 `evidence` 字段逐条核验
- 核验时实际运行（能跑就跑，运行失败即证据不成立），反馈具体报错
- 输出三档结论：`通过 / 部分通过（列出缺哪条）/ 不通过（列出原因）`，并给出"差一步就能过"的具体建议

## 硬的边界

- 结论必须能指向一条具体证据；无法指向时按"不通过"处理
- 运行只用于核验，学生的项目代码由学生自己写
````
