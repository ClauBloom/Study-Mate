# StudyMate 工程约束

> **定位**：引擎项目的**工程硬约束**——目录与资源约定、模板与生成器的占位符契约、前端技术选型，
> 以及"哪条规则归哪个 skill 管"的指路。产品视角见 [设计方案](设计方案.md)，日常使用见
> [使用说明](使用说明.md)，前端资源引用路径见 [templates/assets/README.md](../templates/assets/README.md)。
>
> 本文档的前身是《实施计划》：那份按任务拆的构建台账（Task 1–14、"已交付"清单、依赖 DAG）
> 已随 v0.1 交付删除，**约束部分留在这里**；改引擎只读本文档与上面那几份。

## 一、三个区域，互不混用

| 区域 | 位置 | 是什么 |
|---|---|---|
| **引擎项目** | `<root>/`（本仓库） | 系统源码：skills 源、preset 源、schemas、templates、scripts、examples、docs。学习时只读 |
| **用户级安装** | `~/.dsh/` | `.agent-presets/learning/`（学习模式预设，里面记录引擎的 skill 目录）与 `studymate-config.yaml`（工作区定位）。由 `install.sh` / `install.ps1` 写入，与会话目录无关 |
| **学习工作区** | 默认 `<root>/workspace/`，可在配置里改 | 所有学习数据：`.learning/`、根主页、各科目主页。布局见 [使用说明 §六](使用说明.md#六学习数据存在哪) |

- **会话可在任意目录启动**：总控开场先读 `~/.dsh/studymate-config.yaml` 拿 `workspace`（记为 `LEARN_WORKSPACE`）与 `root`；读写一律基于这两个路径，**不在会话 cwd 里建或找学习文件**。
- **预设目录 `<root>/preset/learning/` 是源**，`install.sh` / `install.ps1` 负责拷到 `~/.dsh/.agent-presets/learning/`；**禁止直接改 `~/.dsh/` 下那份**。
- 面向学生的输出一律中文；skill 内部指令用中文。

## 二、目录与规则归属

```text
<root>/
├── install.sh / install.ps1   # 装预设 + 建工作区（macOS-Linux / Windows）
├── .dsh/skills/               # 平级一层，DSH 只扫一层找 SKILL.md
│   ├── learning-system/       # 总控（唯一被模型加载的入口）
│   ├── resource-scout/  image-scout/  curriculum-designer/     # 角色：两个调用面都关
│   ├── learning-coach/  practice-evaluator/                    # 角色：两个调用面都关
│   └── lesson-design/ layered-practice/ evidence-check/ local-qa/ record-keeping/   # 协议：可被 skill 工具加载
├── preset/learning/           # 预设源（agent.cordis.yml 里的 skill 目录由安装脚本写入）
├── schemas/                   # 5 份：curriculum / progress / assessment / session-summary / subject
├── templates/                 # 页面骨架 + 工作区文件模板 + assets/（前端资源源）
├── scripts/                   # 生成与校验（下表）
├── examples/                  # 示例工作区镜像：两门示例科目
├── docs/                      # 使用说明 / 课件内容格式 / 设计方案 / 工程约束（本文）+ images/
└── workspace/                 # 学习数据（默认位置，已 gitignore）
```

**规则归属（一处定义，别处只给指针）**：

- **课件**的唯一约束来源是 `lesson-design`（要素／实操规范／讲法倾向／记忆难度／贯穿线索／复用骨架）
- **题目**的唯一规范是 `layered-practice`，出题与评估归 `practice-evaluator`
- 完成证据核验 `evidence-check`、局部答疑 `local-qa`、学习状态读写 `record-keeping`
- 本文档只写**路径与工程硬约束**，不重复上面那些内容

**分工原则**：角色 skill 只定义"职责 + 做法 + 输入输出格式"，不碰别的角色的文件；总控是唯一被模型直接加载的入口，且**信息源在它上下文里的活（答疑、盘问、四份元数据、全部档案记录）它自己干**；只有需要外部检索／大量生成／独立验证的活才派角色。

**技能调用面**（`.dsh/skills/*/SKILL.md` 的 frontmatter，用 `scripts/check_skill.py` 校验）：

- 总控与 5 个协议允许模型按名字加载（`skill` 工具）；**5 个角色两个面都关**（`disable-model-invocation: true` + `user-invocable: false`），只作为磁盘上的规格文件，由总控在派发 prompt 里内联要点
- 预设用 `customSkillDirs` 指向 `<root>/.dsh/skills` 并设 `includeDefaultRoots: false`：学习会话只加载本项目技能，也不往 `~/.dsh/skills/` 装链接

## 三、模板与生成器的占位符契约

模板只放骨架与样式，**数据位置用占位符 HTML 注释**（`<!-- @LEARN:XXX -->`），由 `gen_home.py` 替换；
**区块级占位符必须独立成行**（按整行替换），**字段级可嵌在标签内**（按值替换、出现几次换几次）；
**模板里不放示例数据**（示例在 `examples/`）。

| 模板 | 占位符 | 粒度 | 替换成 |
|------|--------|------|--------|
| home-index.html | `@LEARN:SUBJECT_CARDS` | 区块 | 全部科目卡片（`learn-subject-list` > `syo-card.learn-subject-card`） |
| subject-index.html | `@LEARN:TITLE` | 字段 | 科目名（`<title>` 与 `<h1>` 两处都替换） |
| subject-index.html | `@LEARN:STATUS` | 字段 | 科目状态徽标（`syo-tag.learn-status.learn-status--active/--paused/--done`） |
| subject-index.html | `@LEARN:MISSION` | 字段 | 使命一句话（MISSION.md 的 Why 第一句） |
| subject-index.html | `@LEARN:PROJECT` | 区块 | 项目里程碑（progress.yaml 的 project；没有项目时输出 `.learn-project__none` 提示） |
| subject-index.html | `@LEARN:ROADMAP` | 区块 | 分层路线图（`learn-roadmap` > `learn-level` > `learn-node`）；有课件的节点是 `details.learn-slot` + `summary.learn-node` + 子卡片组 `.learn-node__children` |
| subject-index.html | `@LEARN:ATTACHMENTS` | 区块 | 附件分组（参考文档／术语与资源／学习记录／会话摘要；空分组整组省略） |

- **每个占位符上方都写明了生成器必须遵守的结构**，以模板里的注释为准
- **class 约定**：状态着色用 class（`learn-node--todo` / `--learning` / `--done` / `--review` / `--verified`；学习中与初步理解同用 `--learning`）而非内联颜色；生成器只输出结构 + class
- **生成的数值不占位**：状态概览条、知识点与课件计数由页面脚本从 DOM 统计（无 JS 时显示 `–`，不会显示错误的 0）
- 生成器必须**原样保留模板其余内容**，只替换占位符行；区块占位符缺失时报错退出；写完做链接自检

**脚本一览**（用法 `python3 scripts/<名字> --help`）：

| 脚本 | 干什么 |
|---|---|
| `gen_home.py` | 读模板 + 科目数据 → 写根主页与各科目主页（含链接自检） |
| `render_lesson.py` | 内容文件 + 题库 → 课件 HTML（`--check` 只校验不写盘） |
| `check_curriculum.py` / `check_lesson.py` / `check_pool.py` / `check_skill.py` | 四道校验：大纲 / 课件 / 图片库 / 技能 frontmatter |
| `preview_templates.py` | 用假数据把主页模板渲到 `.preview/`（只看样式与交互） |
| `renumber_lessons.py` / `apply_empty_reasons.py` | 课件位次重排 / 把无题理由打进内容文件 |
| `scripts/tests/run_tests.sh` | 回归测试（`--browser` 加真实 Chrome 那 2 套） |

## 四、前端技术选型

Sayo UI（自研零依赖 CSS 框架 + 交互引擎，MIT，vendored 在 `templates/assets/sayo/`）作组件基座 +
`learn-theme.css` 作**共享主题层** + `learn-theme.js` 作**共享行为层**（主题逻辑 + 代码块高亮）。
三个页面共用一份，页面里不要各写一套。

- **主题默认暗色**（首帧 `<html data-theme="dark">`，`LearnTheme.apply()` 兜底也是 `dark`）；优先级 `?theme=` > `localStorage['le-theme']` > 默认暗色。亮色是覆盖层，暗色是保底
- 课件层 `style.css` + `quiz.js` + `lesson-toc.js` **叠在 Sayo 之上**，按科目各拷一份；共享层（`sayo/`、`learn-theme.*`、`learn-mascot.png`）全工作区一份
- **装饰性交互（自定义光标／光晕／拖尾／波纹）一律不开**；只开科目页课件目录的惯性滚动
- 根主页抬头是「透明看板娘 + 发光品牌字」（`learn-mascot.png`），星点层与蓝图网格层都已撤
- 新增/改名共享文件时**清单分散在三处**，必须同时改：`templates/assets/README.md`、`scripts/preview_templates.py` 的 `shared_files`、`scripts/gen_home.py` 的 `ensure_shared_assets`

## 五、几条实测过的坑

- **YAML 里的日期一律加引号**：`created_at: "2026-09-15"`。不加引号会解析成日期对象，schema 要求字符串，校验失败
- **YAML 值里出现 `": "` 必须加引号**（例如 `Cache-Control: no-store`），否则解析报 mapping values are not allowed here
- **skill frontmatter 用 `scripts/check_skill.py` 校验**：直接 `yaml.safe_load` 整个 `SKILL.md` 会因多文档报 ComposerError
- **写给工作区的路径一律钉成绝对路径**（配置是机器全局的，留相对路径换个目录开会话就找不到工作区）
- `curriculum.yaml` / `progress.yaml` / `assessment` / `session-summary` / `subject.yaml` **按 `schemas/*.json` 校验后才算交付**
