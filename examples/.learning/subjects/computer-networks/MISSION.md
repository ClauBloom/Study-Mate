# Mission: 计算机网络

## Why

会连 WiFi、会用浏览器，但说不清一次网页请求中间发生了什么。想把这个黑洞补上：出了网络问题能自己判断卡在哪一层，而不是重启路由器、换浏览器、等它自己好。远期想读得懂 RFC 与厂商文档，把「听说的」换成「查证的」。

## Success looks like

- 能用浏览器与 Wireshark 的抓包，把一次自己的网页请求从域名解析到 TCP 关闭逐段讲出来，指出每一层加了什么头
- 拿到一个 IP 与掩码，能手算出网络地址、广播地址与可用地址范围，并说出这个包下一跳交给谁
- 能写一个 Python TCP 回显客户端，并用抓包解释它的建立、传输与关闭
- 网络出问题时，能说清是名字解析、路由、还是对方程序没响应，再去查对应那一层

## Constraints

- 每周 3~4 次、每次 40 分钟；一个知识点一节课
- 前置：Python 能写小脚本（读写文件、跑循环、装包）；C 语言上过一学期，指针生疏；网络零基础
- 偏好：先讲「这解决什么问题」，拿具体数字走一遍，最后才给定义和符号；讨厌一上来堆术语
- 看不见的过程要具体化：抓包、计数器、具体字节数是主要教具

## Out of scope

- 物理层细节（编码、调制、光纤与双绞线的电气特性）——用到再查
- 网络编程框架与异步 IO（asyncio、aiohttp）——先把一次请求看清
- 网络安全攻防（ARP 欺骗、DDoS 缓解）——先有正常流程的底子
- 路由器与交换机的配置命令（VLAN、ACL、动态路由协议）——本课只解释它们的转发行为
