# 学习记录 0001 · 分层模型与封装

- 节点：`net.layers`
- 日期：2026-09-21（首次学习）、2026-09-23（评估）
- Status: active

## 观察到的证据

1. 用自己的话复述了分层的收益：换掉某一层的实现（以太网换 WiFi）时其他层不用重写——不是背定义，是拿同一份课件的例子换了个说法
2. 在 `curl -v` 的输出里逐行指出了 `Trying 93.184.216.34:80` 属于网际层与传输层、`> GET / HTTP/1.1` 属于应用层，依据是"这一行在读地址还是读请求"
3. 2026-09-23 评估中主动举出 NAT 作为"实现会跨层"的反例，并说清了改端口的原因（多台内网机器共用一个公网地址）

## 这次理解到什么程度

- 分层与封装：能自己画出四层与"每层加一个首部"的图，能报出 20 + 20 + 14 + 4 这四段数字
- 对等层与中间设备：知道交换机看帧头、路由器看 IP 首部，也知道中间设备要看得更高就说明它已经在做应用层的事
- 状态置「能独立应用」，掌握度 0.85（评估记录 `assessments/0001-net.layers.md`）
