## 回车之后发生了什么

在浏览器地址栏敲下 `example.com` 再回车，页面大约两百毫秒后出现。这两百毫秒里机器做了一长串动作：把域名换成 IP 地址，跟对方建立起一条能重发的连接，把请求文本切成小块，每块装进信封送上线路，收到回信后再按相反的顺序拆回来。

要把这一长串一次讲完，很少有人能记住。工程上的办法是把它切开，一段只解决一个问题，再规定段与段之间怎么交接。切出来的每一段叫**一层**。

## 分层这个想法从哪来

1974 年，Vint Cerf 与 Robert Kahn 发表论文《A Protocol for Packet Network Intercommunication》，第一次把"多个网络互联"这个问题拆成若干层来描述。当时每家厂商的机器各有一套通信做法，互相接不上；把职责分开、只固定层与层之间的接口之后，不同厂商的设备才可能拼在一起。

1984 年 ISO 提出七层的 OSI 参考模型，定义很细，实现与市场都没跟上。真正铺开的是 IETF 维护的 TCP/IP 模型，它把同样的想法压成四层：

| 层 | 管什么 | 这一层用的地址 | 数据单元 |
| --- | --- | --- | --- |
| 应用层 | 这次通信要办什么事 | 域名、URL | 报文 |
| 传输层 | 哪两个程序在说话，丢了要不要重发 | 端口号 | 报文段 |
| 网际层 | 从哪台机器到哪台机器，走哪条路 | IP 地址 | 分组（包） |
| 网络接口层 | 这一段线路上，帧交给哪块网卡 | MAC 地址 | 帧 |

**分层**（layering）指的就是这件事：把一次通信的职责拆成若干层，每层只跟自己的上下邻居打交道；跨机器通信时，只有对端的同一层才读得懂这一层写的首部。

层数怎么切是人为约定。不少教材把最下面那层再拆成"数据链路层 + 物理层"，凑成五层；两种切法描述同一个系统，只是粗细不同。本课统一用四层。

::: note 层的名字会变，职责不会
同一件事在不同书里叫法不同：网际层也叫网络层，网络接口层也叫链路层。认职责比记名字有用——听到一个新叫法，先问它管的是地址、是重发、还是线路。
:::

## 封装：每层加一个首部

邮政系统寄一封信是层层套封的：信纸装进信封，信封上写收件地址；邮局再把一批信装进邮袋，袋子上写目的地城市。每层只读自己这层封面上写的字，不拆开里面的东西。

网络里做法相同，术语叫**封装**（encapsulation）：上层交下来的整块数据被当作**载荷**（payload），本层在它前面加上自己的**首部**（header），再交给下一层。首部里装的全是本层要用的信息，载荷对它只是一串不解释的字节。

- 应用层写好的 HTTP 请求交给传输层，传输层在它前面加上 TCP 首部（无选项时 20 字节）
- 传输层交下来的报文段交给网际层，网际层在前面加上 IP 首部（IPv4 无选项时 20 字节）
- IP 包交给网络接口层，这一层在前面加 14 字节帧头，在末尾再加 4 字节校验

"首部"这个叫法来自早期报文格式：地址、长度、校验这些字段写在整块数据的最前面。字段多了以后也有写在后面的，那叫尾部，以太网的校验就属于尾部。

## 一个具体数字走一遍

设一条 `GET /index.html HTTP/1.1` 的请求连同几个请求头共 78 字节，从应用层往下走：

- 传输层加 20 字节 TCP 首部，98 字节
- 网际层加 20 字节 IP 首部，118 字节
- 网络接口层加 14 字节帧头与 4 字节帧尾校验，136 字节

真正跑在线路上的是 136 字节，其中 78 字节是内容，58 字节是各层加的首部，占四成还多。小请求上这个比例一直很难看，这也是后来 HTTP/2 要做头部压缩的原因之一。

对方收到后反过来做：网卡核对校验、去掉帧头，网际层去掉 IP 首部，传输层去掉 TCP 首部，应用层拿到那 78 字节原文。这个过程叫**解封装**。整条路上，中间设备只看得到自己那一层：交换机看帧头，路由器看 IP 首部。

## 边界与反例

四层模型写的是职责分工，真实实现经常越界：

- 家用路由器做地址转换时要同时改 IP 首部里的地址与 TCP 首部里的端口，一次动两层
- TLS 夹在应用层与传输层中间，两层都不完全属于
- HTTP/3 把传输层的 TCP 换成基于 UDP 的 QUIC，四层骨架没变，某一层的实现整个换掉
- 负载均衡与防火墙要看端口甚至请求内容，它们读的层次比"路由器只看到第三层"高得多

模型的价值在定位问题：网页打不开时，先分清是名字没解析、路径不通、还是对方程序没响应，再挑对应的那层去查。反过来，把模型当成"实现必须逐层调用、谁也不许跨界"的规定，就会得出跟现实对不上的结论。

顺手记两个数字：以太网一个帧能装的载荷上限是 1500 字节（MTU），减去 20 字节 IP 首部与 20 字节 TCP 首部，TCP 一次能交给 IP 的数据最多 1460 字节（MSS）。下一课讲帧的时候还会回到这两个数。

::: practice 上手做 | 第 1 步 · 在输出里认层

打开浏览器按 `F12`，切到 Network 面板，刷新一次页面，点开第一条请求看 Headers。
把 `Host`、`User-Agent`、`Accept` 三行抄下来，回答两个问题：这三行是谁写进去的？它们属于哪一层的首部？

再在终端里跑一次 `curl`，输出里每一行的归属层都能对上号：

```term
$ curl -v http://example.com
*   Trying 93.184.216.34:80...
* Connected to example.com (93.184.216.34) port 80
> GET / HTTP/1.1
> Host: example.com
> User-Agent: curl/8.5.0
>
< HTTP/1.1 200 OK
```

`*` 开头的是 curl 报告的本地过程：域名解析出地址、与 80 端口建立连接，落在网际层与传输层。
`>` 是它发出去的应用层首部，`<` 是对方回的应用层首部。把这三类逐行指出来，再往下看。
:::
