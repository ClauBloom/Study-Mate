## 一根网线接出来的问题

实验室里二十台机器插在同一台交换机上。其中一台要发数据给另一台，它得先回答：这段线路上挂着二十块网卡，这一包该交给谁？

上一课说网络接口层用 MAC 地址、数据单元叫帧。这一课把帧拆开看：地址写在哪几个字节里，交换机会读哪一段，跨网段时这些地址又怎么变。

## 以太网这个名字的来历

1973 年，Bob Metcalfe 在施乐帕克研究中心（Xerox PARC）做出第一版以太网，用来把几台 Alto 计算机和一台打印机连起来。1976 年他与 David Boggs 发表论文《Ethernet: Distributed Packet Switching for Local Computer Networks》，把做法讲清楚：所有机器共享一根同轴电缆，发之前先听，线上安静才发，撞上了各自退避一段随机时间重发。

名字里的"以太"（ether）借自 19 世纪物理学假想的传播介质"光以太"。Metcalfe 用这个词表示数据在共享介质里传播，与物理上的以太没有关系。

1980 年 DEC、Intel、施乐三家联合发布 DIX 以太网标准，1983 年 IEEE 把它收进 802.3。此后介质从同轴电缆换到双绞线、光纤，速率从 2.94 Mb/s 涨到 400 Gb/s，帧格式基本没动。

| 字段 | 字节 | 装什么 |
| --- | --- | --- |
| 前导码 | 8 | 固定交替的 0 与 1，让接收方对齐时钟；网卡处理完不交给上层 |
| 目的 MAC | 6 | 这一帧给哪块网卡 |
| 源 MAC | 6 | 这一帧从哪块网卡发出 |
| 类型 | 2 | 载荷是什么协议，`0x0800` 是 IPv4，`0x0806` 是 ARP |
| 载荷 | 46 ~ 1500 | 上层交下来的整个 IP 包 |
| FCS | 4 | 帧的循环冗余校验值，接收方算一遍对不上就丢弃 |

46 与 1500 这两个边界不是随手定的。上限 1500 就是上一课说的 MTU。下限 46 来自最小帧长 64 字节：从 64 里减掉 6 + 6 + 2 + 4 得 46，不够就补零。定这条是为了让最早的共享电缆上"撞车"能被发方察觉——帧太短，等发完时冲突信号还没绕回来。帧长定下来之后就没再改：1980 年的 10 Mb/s 与今天的 400 Gb/s 用同一个格式，改了就跟老设备说不上话。

## MAC 地址怎么编号

MAC 地址是网卡的 48 位编号，写成六组两位十六进制数，如 `02:1a:2b:3c:4d:5e`。前 24 位是 IEEE 分配给厂商的编号（OUI），后 24 位由厂商自己给每块网卡编。它出厂时烧进 ROM，操作系统允许驱动改写，所以更像出厂编号，不承担身份认证。

地址分三类，看第一个字节就能判：**单播**地址最低位为 0，一块网卡一个；**组播**地址最低位为 1，一组网卡订阅同一个地址，一次发送这一组都收；**广播**地址 `ff:ff:ff:ff:ff:ff` 则本段线路上所有网卡都收，交换机必须向所有端口转发。

## 交换机在做什么

最早的以太网所有机器共享一根电缆，任何两台同时发就撞车。交换机换了做法：每个端口一条独立链路，端口之间由交换芯片按需接通，同一时刻可以有多对端口通信。

它维护一张 MAC 地址表，记"哪个地址在哪个端口"，工作流程只有三步：

1. 收到帧，把源 MAC 与收到它的端口写进表里（自学，不用配置）
2. 拿目的 MAC 查表，查到就从对应端口发出去，其他端口收不到
3. 查不到，或目的是广播地址，就向除入口外的所有端口各发一份，这叫泛洪

表项有存活时间，几分钟不用就删掉；机器换端口、换网卡，表会自己重新学。因此交换机把"冲突域"缩小到单个端口，**广播域却没变**：广播帧仍会淹没整个交换网络，要切分得靠路由器或 VLAN。

## 知道 IP 却不知道 MAC

网际层交下来的是 IP 包，里面写着目的 IP 地址，而帧头要填目的 MAC 地址。两者之间需要一次翻译，1982 年的 RFC 826 给这个翻译定了规则，叫地址解析协议（ARP，Address Resolution Protocol）。过程只有一问一答：

- 问：广播一个 ARP 请求，"谁的 IP 是 192.168.1.1？请把 MAC 告诉我"，目的地址填广播地址，同网段所有机器都收到
- 答：只有 IP 匹配的那台机器单播回一个应答，带上自己的 MAC

问到的结果存进 ARP 缓存，几分钟内直接用，不重复广播。缓存记录过期后会重新问一遍——换网卡、换路由器之后连不上，先清一次 ARP 缓存往往就好了。

## 边界与反例

- **MAC 地址只管一段链路**：跨网段时源与目的 MAC 在每一跳都换成"当前设备 → 下一跳"的地址，IP 包本身不动；下一课会把这条路走一遍
- 交换机不读 IP：它按 MAC 转发，所以同网段的机器插在同一台交换机上就能通，不必经过路由器
- Wi-Fi 不用以太网帧：802.11 有自己的帧格式，但上层看到的仍是一个网络接口层，IP 包照样装进去
- VLAN（802.1Q）在帧头插 4 字节标签，用标签而不是物理端口划分广播域；帧因此最长到 1522 字节
- MAC 地址可以伪造：改一下驱动就能冒充别人的地址，所以它不构成身份证明

::: practice 上手做 | 第 1 步 · 把自己网卡的地址拆开看

先读本机的地址表与邻居表（Linux；Windows 用 `ipconfig /all` 与 `arp -a`）：

```term
$ ip -brief link show
lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP>
wlp3s0           UP             3c:58:c2:1a:7f:0d <BROADCAST,MULTICAST,UP,LOWER_UP>

$ ip neigh show
192.168.1.1 dev wlp3s0 lladdr 8c:53:c3:04:1e:a8 REACHABLE
```

回答三个问题，每个都写出依据：

1. `wlp3s0` 的地址是单播还是组播？第一个字节的哪一位告诉你的？
2. `192.168.1.1` 那一行的 MAC 是谁的网卡？它为什么出现在你的邻居表里？
3. `lo` 的地址为什么是全 0？

再用 Python 读一次本机地址，对照上面的输出：

```python
import uuid

print(f"{uuid.getnode():012x}")
```

读不到硬件地址时它返回一个组播位为 1 的随机值，所以这个数不能当真实 MAC 用；反过来，看到第一个字节的组播位是 1，也能认出它不是一块普通网卡的地址。
:::
